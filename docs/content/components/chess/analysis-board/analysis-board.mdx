## Purpose

The board a teacher transcribes a game on. Moves played on the board are written into the move list; going back and playing something else opens a variation; each move can carry a comment, quality and evaluation signs, and arrows drawn with the right button. The result is a PGN.

It is built to sit **inside a `<form>`**: the PGN is published in a hidden input named by `name`, so saving is an ordinary submit and the server action reads `formData.get("pgn")` like any other field. The component knows nothing about where the game goes.

It does not replace the [`GameViewer`](/components/chess/game-viewer/game-viewer). The viewer is the student's reader, which since the studies feature can also edit in place; this is the teacher's authoring tool with a paste box, a comment tab and a discard button. All the chess logic is in `lib/chess/pgn-edit.ts`; this file holds interface state only.

## Props

| Prop | Type | Required | Meaning |
| --- | --- | --- | --- |
| `name` | `string` | yes | Name of the hidden input the PGN travels in. |
| `defaultPgn` | `string` | no | The game to start from. Empty or unparsable falls back to `initialFen`. |
| `initialFen` | `string` | no | Starting position when there is no previous PGN; omitted means the standard start. |
| `orientation` | `"white" \| "black"` | no · default `"white"` | Which side starts at the bottom; the flip button toggles on top of it. |
| `onAutoSave` | `(pgn: string) => Promise<boolean>` | no | Saves on its own after a pause, returning whether the write succeeded. Optional on purpose: without it the component behaves as a plain form field, which is what a screen whose saves have side effects wants (a lesson save marks its frozen exercises stale, so autosaving there would invalidate them while typing). |

## Behaviour

**Source of truth.** A mutable chessops `Game` lives in a ref; after every change it is reserialised and the PGN string is what renders and what is sent. Two representations that could drift are avoided by deriving one from the other every time. The starting game and its PGN are computed once into `baseline`; "unsaved changes" is `pgn !== baseline.pgn`, never a separate flag.

**Editing.** `onMove` from the board calls `addMove` at the current path and jumps to the new move; drawing calls `setShapes`; the comment textarea calls `setCommentText` on every keystroke (through a local draft, so typing a space does not get trimmed away); the two NAG groups (move quality, position evaluation) are exclusive within their group. Promote, promote one step and delete come from the [`MoveContextMenu`](/components/chess/game-viewer/move-context-menu) and go through `mutateKeepingPlace`, which keeps a reference to the node before mutating and asks where it ended up, because promoting reindexes siblings. "Comentar" and "Anotar" in the menu select the move and switch to the matching tab, focusing the textarea on the next frame.

**Paste.** "Pegar un PGN" opens a textarea capped at `PGN_MAX_LENGTH`; an unreadable PGN shows a `role="alert"` error and nothing is replaced.

**Autosave.** Only with `onAutoSave`: a 1.5 s timer after the last change saves the latest PGN; a change during the wait restarts it, so intermediate versions are never sent. `lastSaved` is what the server confirmed; the status text is derived by comparing (`error` wins over everything, then `saving`, then `unsaved`, then `saved`) and announced with `aria-live="polite"`. A `beforeunload` handler warns when `pgn !== lastSaved`. Without `onAutoSave`, the footer shows "Hay cambios sin guardar." and a "Descartar cambios" button that rebuilds the baseline game.

**Keyboard.** Arrow keys move through the game except while typing in an input or textarea. Unlike the viewer there is no viewport check: only one analysis board is ever on a page.

**Warnings.** Illegal moves in a pasted PGN are listed above the board (`tree.warnings`), in every environment, because the author has to fix them before saving.

## Usage

From `components/platform/sections/teacher/classes/class-block-editor/block-form.comp.tsx`:

```tsx
import { AnalysisBoard } from "@/components/chess/analysis-board/analysis-board.comp";

<AnalysisBoard name="pgn" defaultPgn={block?.pgn ?? undefined} />
```

The surrounding `<form action={boundAction}>` receives the PGN as `formData.get("pgn")`.
