## Purpose

A diagram of a position, the way a book prints one: nothing moves, nothing loads. The FEN placement is parsed into 64 glyphs and rendered as a `<figure>` with a grid of `<div>`s; the pieces are the SVG files in `public/pieces`, painted as CSS backgrounds by the piece modifiers. Because it is a Server Component it costs zero client JavaScript, which is why the class content renderer uses it for `POSITION_REF` blocks and the blog uses it for its diagram block.

The blog block used to be a copy of this component with its own stylesheet, and the two drifted apart; it is now a one-line adapter that passes `context="article"`. Keep it that way: one diagram, two contexts.

For a position the reader should navigate, use the [`GameViewer`](/components/chess/game-viewer/game-viewer).

## Behaviour

No state, no effects. `parseFenPlacement` returns the 64 squares in board order (rank 8 first); the component reverses them for the black orientation, computes light/dark from file and rank parity, and emits one `static-diagram__square` per cell with a `static-diagram__piece` inside when the cell is occupied. The glyph name (`w-king`, `b-pawn`…) becomes the piece modifier, which is where the SVG is referenced.

With `arrows`, an SVG over the grid (`viewBox="0 0 8 8"`, one unit per square, `aria-hidden`: what the arrows say is written beside the diagram by whoever passes them) holds one filled `<polygon>` per arrow, its points computed by `arrowPoints` from the two squares and the orientation — a shaft and a head whose tip stops short of the square's centre, so the piece there stays readable. A square that does not exist, or the same square twice, draws nothing.

## Markup & styling

Block `.static-diagram` (200 lines).

**Elements:** `.static-diagram__grid` (8×8, `aspect-ratio: 1`, `position: relative` for the arrows), `.static-diagram__square`, `.static-diagram__piece`, `.static-diagram__arrows` (the SVG over the grid), `.static-diagram__arrow`, `.static-diagram__circle` (a ring round a square), `.static-diagram__caption`

**Modifiers and states:** `.static-diagram__square_light`, `.static-diagram__square_dark`, `.static-diagram__square_last-move` (an amber layer under the piece, `::before`, that takes the amber's hue and the square's lightness), `.static-diagram__piece_glyph_{w,b}-{king,queen,rook,bishop,knight,pawn}` (twelve rules, each a `background-image: url("/pieces/….svg")`), `.static-diagram__arrow_tone_{danger,success,info,warning}`, `.static-diagram__circle_tone_{danger,success,info,warning}`, `.static-diagram_context_article` (switches the caption colour and scale to the article's), `.static-diagram_look_material` (points `--board-light`/`--board-dark` at the material board's tokens and the twelve pieces at `public/pieces/elegida/`)

**Tokens:** `--board-light`, `--board-dark` (the same square colours as the live board), `--platform-space-3` (the caption's distance from the grid), `--platform-type-lg`, `--platform-type-sm` (article context), `--platform-text-muted`, `--color-muted-on-light` (article context), `--platform-danger` and `--platform-success-ink` (the arrows, platform only)

No media queries: the grid is fluid, up to 420px. The caption does not inherit the surrounding text size, it sets its own: `--platform-type-lg` on the platform and `--platform-type-sm` inside an article. Each token carries the site's size as its fallback (`var(--platform-type-lg, 16px)`, and 14px the article's), because the blog draws it without `platform.css`.

## Usage

From `components/platform/shared/class-content-renderer/class-content-renderer.comp.tsx`:

```tsx
import { StaticDiagram } from "@/components/chess/static-diagram.comp";

<StaticDiagram
  fen={block.position.fen}
  orientation={block.position.orientation}
  caption={block.caption ?? block.position.title}
/>;
```

From the blog block, `components/site/sections/blog/article-content/blocks/chess-diagram-block.comp.tsx`:

```tsx
<StaticDiagram fen={fen} orientation={orientation} caption={caption} context="article" />
```
