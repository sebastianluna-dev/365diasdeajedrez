## Purpose

**The** platform's game viewer. Lessons, the studies' games, class blocks, the teacher's view of a student's game and the two position pickers all mount this same component. Do not create parallel viewers: a new need is a new prop or slot here.

It renders a board with a notation panel next to it, the four navigation buttons plus flip, an options menu (sound, fullscreen), optional player strips, an optional engine with an evaluation bar, and slots for whatever each screen needs around it (title, badge, header actions, a footer under the board, position actions). With `editable` and `onPgnChange` it becomes an in-place editor: moves are played on the board, arrows are drawn, right-clicking a move opens its menu. There is no separate editing screen; the game is annotated where it is read.

The viewer never saves and never fetches. It receives a PGN, reports the current path and, when editing, reports the new PGN; the screen that mounts it owns persistence.

## Behaviour

**Tree and current path.** `parsePgnTree(pgn)` is memoised. The current path is `path ?? selectedPath`, resolved at render time to the closest existing ancestor when the PGN changed underfoot (an undo, a deleted branch), so there is never a frame with the board at the start. Every path change is both stored and reported through `onPathChange` (kept in a ref so the parent need not memoise). An unparsable PGN renders a single error paragraph with the `_state_error` modifier.

**Navigation.** First, previous, next, last read the current path from a ref so holding "previous" or "next" keeps traversing: 400 ms before the repeat starts, then one move every 130 ms, stopped on pointer up, leave or cancel. Arrow keys work only while the viewer is at least 60 % in view or has been clicked (there may be several on a page) and never while typing in an input, textarea or contenteditable.

**Flip, sound, fullscreen.** Flip is a game action and sits with the navigation buttons. Sound and fullscreen are viewer settings and live in the options menu (`role="menu"`): opening it moves the focus to the first option, Up and Down walk the options and wrap around, Escape and choosing an option close it and hand the focus back to the button, an outside click closes it without touching the focus. It unfolds upwards from the button and folds back: closed, it stays mounted for 120 ms through [`useLingering`](/components/chess/game-viewer/use-lingering-hook) with `.game-viewer__options-menu_state_closing`, unpressable, and the same hook keeps the [`MoveContextMenu`](/components/chess/game-viewer/move-context-menu) for its exit. The sound toggle is a `menuitemcheckbox` backed by [`viewer-preferences`](/components/chess/game-viewer/viewer-preferences) through `useSyncExternalStore`, so every viewer on the page shares it and the server paint uses the default. Fullscreen state is read from `document.fullscreenElement` on `fullscreenchange`, because Escape leaves it without the button. A move sound plays on position change (capture when the piece count drops), never on mount.

**Height.** The notation column measures what the board does, never what the game does. The two share one `auto` grid row, which would otherwise grow to the taller of them, so `.game-viewer__panel-column` has `height: 0; min-height: 100%`: it contributes nothing to the row, the board alone sets it, and the column then takes that whole row. The move list scrolls inside the card and the engine, switched on, takes room from the list instead of pushing the card below the board. Full screen undoes it (`height: auto`), because there the row is `1fr` of the screen.

**Engine.** `useEngine(fen, engine && engineOn)` lives here and not in the panel because two far-apart places consume it: the evaluation bar next to the board and the panel's lines. The bar's slot is reserved whenever `engine` is true so switching it on does not move the layout; it fills from the bottom with White's advantage. `engineExpanded` is tracked here because the height an expanded line takes is given up by the notation.

**Editing.** `isEditing = editable && Boolean(onPgnChange)`. Then the board becomes interactive with editable shapes, `onMove` calls `editing.addMoveAt`, `onShapesChange` calls `editing.updateShapes`, and both move lists receive `onContextMenu`, which opens the [`MoveContextMenu`](/components/chess/game-viewer/move-context-menu) with `canPromote` and `canPromoteOneStep` derived from the path (all-zero segments means main line; last segment `0` means first sibling). Comment and annotate items are offered only when the viewer has `tools` (the panel they lead to) and never in fullscreen. All mutations go through [`usePgnEditing`](/components/chess/game-viewer/use-pgn-editing-hook).

**Development aid.** Outside production, PGN warnings (illegal moves) are listed at the top so an author can fix the source.

## Usage

Read-only, from `components/platform/sections/courses/lesson-view/lesson-view.section.tsx`:

```tsx
import { GameViewer } from "@/components/chess/game-viewer/game-viewer.comp";

<GameViewer
  pgn={lesson.pgn}
  orientation={lesson.orientation}
  moveList="flow"
  title={`${lesson.order}. ${lesson.name}`}
  subtitle={subtitle}
  description={lesson.description}
  badge={lesson.isPriority ? "Prioridad" : undefined}
  skip={
    lesson.nextLessonHref && (
      <Link
        href={lesson.nextLessonHref}
        className="lesson-view__skip"
        title="Pasar a la siguiente lección sin marcar esta"
      >
        Saltar
      </Link>
    )
  }
/>;
```

Editing, with the engine, the players and the tools, from `components/platform/sections/studies/game-view/game-view.section.tsx`:

```tsx
<GameViewer
  pgn={pgn}
  controls="panel"
  engine
  editable={game.canEdit}
  onPgnChange={applyPgn}
  players={{
    white: { name: game.white, elo: game.whiteElo, title: game.whiteTitle, country: game.whiteCountry },
    black: { name: game.black, elo: game.blackElo, title: game.blackTitle, country: game.blackCountry },
  }}
  tools={{ saveLabel }}
/>
```

Nothing is passed as JSX: the section holds the PGN (two things write it and the autosave reads it) and the viewer owns the path, the tools' tab and the strips.
