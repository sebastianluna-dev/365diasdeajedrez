## Purpose

The notation as prose. Moves run on one after another and a **comment breaks the line**: the run closes carrying the move the comment explains, the comment follows as its own paragraph, and the line resumes below with its number repeated ("3… Ab4"). That is how a lesson is read — a paragraph of moves, then what is said about the last of them, with the board alongside.

Variations stay inline, in parentheses: a variation is an aside inside the line it hangs from, so even its own comments stay in the parenthesis instead of breaking the page over a move nobody is following.

This is the list a **lesson** uses; a game consulted move by move uses the [`MoveTable`](/components/chess/game-viewer/move-table).

The tree carries no editing logic. It reports a right click when asked to and nothing else, so the student's viewer never ships menu code.

## Props

| Prop            | Type                                        | Required | Meaning                                                                                                                                                                     |
| --------------- | ------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tree`          | `PgnTree`                                   | yes      | The parsed game from `parsePgnTree`.                                                                                                                                        |
| `currentPath`   | `string`                                    | yes      | Dotted path of the active node; `""` is the initial position.                                                                                                               |
| `onSelect`      | `(path: string) => void`                    | yes      | Click on a move.                                                                                                                                                            |
| `onContextMenu` | `(path: string, event: MouseEvent) => void` | no       | Right click on a move. Optional on purpose: whoever only reads the game does not pass it and the list behaves exactly as before; an editor uses it to open the move's menu. |

## Behaviour

- Where the line is cut is not decided here: `buildProseBlocks` (`lib/chess/notation-prose`) returns the runs and comments in reading order, already labelled in Spanish piece letters with their NAG glyphs. It is a pure module with tests, because the subtle part — when a move has to repeat its number — is checked far better that way than by looking at a screen.
- The component walks that list and draws it: a run becomes a `<p>` of buttons, a comment a `<p>` of text, a variation a nested span.
- The active move's button is kept in view with `scrollIntoView({ block: "nearest", inline: "nearest" })` on every path change: the minimum scroll, in the scrolling container only, so the page does not jump.
- With `onContextMenu`, the button's `onContextMenu` prevents the browser menu and forwards the path and the event (the viewer needs the pointer position to place its menu).

## Markup & styling

Block `.move-tree` (84 lines).

**Elements:** `.move-tree__line` (a run of moves), `.move-tree__comment` (a paragraph of the lesson), `.move-tree__move`, `.move-tree__aside` (a comment inside a variation), `.move-tree__variation`

**Modifiers and states:** `.move-tree__move_active`

**Tokens:** `--move-tree-font-size` (set by the viewer's panel so the list scales with it), `--platform-accent-ink`, `--platform-accent-soft`, `--platform-surface-neutral`, `--platform-text`, `--platform-text-muted`, `--platform-text-subtle`

No media queries; it wraps as text.

## Usage

From `components/chess/game-viewer/game-viewer.comp.tsx`:

```tsx
import { MoveTree } from "./move-tree.comp";

<MoveTree
  tree={tree}
  currentPath={currentPath}
  onSelect={setCurrentPath}
  onContextMenu={isEditing ? openMenu : undefined}
/>;
```
