## Purpose

What the App Router shows in a segment while its Server Components await data. Every `loading.tsx` under `app/(platform)` returns this, so the platform has one loading look and the files are one line each: a knight hopping over its shadow and a line, "Cargando…" by default. The study's segment, where opening a study is opening its first game (`/estudios/[studyId]` redirects there), says "Preparando el tablero…" instead. That is the wait of **arriving** at a screen. Two segments have another, for moving inside a screen whose frame stays: between two lessons of a chapter, and between two games of a study, a screen of another shape is worse than the screen's own shape empty, so the lesson's segment renders [`LessonSkeleton`](/components/platform/sections/courses/lesson-view/lesson-skeleton) and the study game's [`GameSkeleton`](/components/platform/sections/studies/game-view/game-skeleton) — the board in its place with a ring turning over it ([`BoardSkeleton`](/components/platform/shared/board-skeleton)). Arriving at a study still shows the knight: that boundary sits on the `[studyId]` segment, above the layout that keeps the study's column.

## Props

| Prop    | Type     | Required                   | Meaning                                                                                                             |
| ------- | -------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `label` | `string` | no · default `"Cargando…"` | The visible text; the study's segment passes "Preparando el tablero…", because what is waited for there is a board. |

## Behaviour

None. The root carries `role="status"` and `aria-live="polite"`; the figure is `aria-hidden`. Under `prefers-reduced-motion: reduce` nothing moves. Its exit cannot be animated, because the App Router unmounts the fallback the moment the page is ready: the page's own fade-in (`.platform-page`, in `platform.css`) is what softens that side of the swap. The swap does not move the header either: `globals.css` reserves the scrollbar's room (`scrollbar-gutter: stable`), so the bar appearing with the longer page changes no width.

## Markup & styling

Block `.board-loading` (99 lines).

**Elements:** `.board-loading__figure`, `.board-loading__knight` (the ♞ glyph, in the platform font), `.board-loading__shadow`, `.board-loading__label`

**Keyframes:** `board-loading-in` (a 200 ms fade after a 120 ms delay: a page that arrives at once never shows it, one that takes longer sees it appear instead of flash), `board-loading-hop` (up 12 px with an 8° tilt at 30 %, back at 60 %), `board-loading-shadow` (narrows to 60 % and fades while the knight is up); 1.3 s, ease-in-out, both at the top level because `@keyframes` cannot be nested.

**Tokens:** `--platform-text`, `--platform-text-muted`

**Breakpoints:** the block fills the height the 70 px bar and the content padding leave, so the figure sits where the board will; `(width < 1280px)` drops that to `60vh` once the bar wraps.

## Usage

From `app/(platform)/estudios/[studyId]/loading.tsx`:

```tsx
import { BoardLoading } from "@/components/platform/shared/board-loading/board-loading.comp";

export default function StudyLoading() {
  return <BoardLoading label="Preparando el tablero…" />;
}
```
