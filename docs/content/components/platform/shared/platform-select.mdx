## Purpose

A native `<select>` cannot be drawn: its list is the browser's. This one is Radix's `Select` primitive, so the trigger looks like the platform's inputs and the list uses the platform's surface, border and selection blue, with keyboard navigation and typeahead for free. Inside a form it behaves like a native select: the primitive keeps a hidden `<select name>` in sync with the choice, so `FormData` carries it.

## Behaviour

- The list is **not portalled**: it renders next to the trigger, positioned against the viewport (`position="popper"`, fixed strategy). A portal to `<body>` would be inert under a modal `<dialog>`'s top layer, and the platform's dialogs are native.
- `--radix-select-trigger-width` and `--radix-select-content-available-height` are set by the primitive from the trigger's box; the stylesheet gives the list the trigger's width and caps its height to the viewport.
- The chosen item carries the check; the highlighted one the selection's tint (`--platform-selection-soft`), or the accent's (`--platform-accent-soft`, in its ink) with `tone="accent"`, which also draws the trigger's focus in the accent. The chevron points down at rest and up while open.
- **The empty option.** The primitive forbids an item whose value is `""`, so `emptyOption` is an item with a private value that the component maps back to `""` before anyone sees it (`onValueChange`, the hidden select, which the primitive gives an empty `<option>` when nothing is chosen). The value is held in the component even when uncontrolled, for that mapping; its check is drawn by hand because the primitive only marks the item whose value is current.
- **The page keeps its scrollbar while the list is open.** The primitive locks the page with `react-remove-scroll`, which hides the body's overflow and pads the gap, so the bar vanished and the page jumped. `platform.css` overrides the lock's `overflow` and `margin-right` on `body.platform-theme[data-scroll-locked]` (by specificity, since the lock's stylesheet is injected later with `!important`); wheel and touch are still stopped by the lock's listeners.
- **It starts again from what was saved.** The select is mounted under the value it opens with (`savedValueKey(defaultValue)`), so a save that changed the choice mounts it anew from it. React resets a `<form action>` when its action finishes, and the primitive answers the form's `reset` by going back to the value it had when it was MOUNTED. On a form that stays on screen after saving, that is the value from before the save: until 2026-09-28 the control showed what had just been replaced, the page had to be reloaded to see what was stored, and saving again without reloading sent the old value and undid the change. A controlled select (`value`) keeps one key: its parent holds the value.
- **The trigger says what is chosen from the first paint.** The primitive resolves the label from its items, which do not exist until the browser mounts them, so a server-rendered select arrived with an empty trigger and filled itself in when the JavaScript landed — a blank field on an otherwise readable page. The label is looked up here (`findOptionLabel`, over `options` and `groups` alike) and handed in as `Select.Value`'s child; it follows the value, which is state, so choosing still changes it.
- **axe's `aria-hidden-focus` on the open list is a false positive.** While the list is open the primitive hides everything outside it from assistive technology (`hideOthers` from `aria-hidden`, which reaches the trigger itself, a sibling of the list), and the trigger keeps its `tabindex`, so axe reports a focusable element inside `aria-hidden`. Nothing can focus it while it is hidden: the list traps the focus (`FocusScope trapped`) and its `keydown` swallows Tab, and outside pointer events are off, so a click on the trigger first closes the list, which takes the `aria-hidden` off, and only then lands the focus. Checked in headless Chrome on the `Open` story (2026-10-02): two Tabs and two Shift+Tabs leave the focus on the option; the click and Escape give it back to the trigger with no `aria-hidden` left. Radix 2.3.7 (`radix-ui` 1.6.7) still does it, and so would any primitive that hides its siblings with `aria-hidden` instead of `inert`; on a real page the same rule would flag every focusable element behind an open select. The `Open` story keeps the rule for every other hidden element and leaves the trigger out (`a11y.config.rules`, with the reason on the line).
- `required` with a `placeholder` and no `defaultValue` works like a native required select: the hidden select is `required`, the browser blocks the submit and reports it on the hidden control, which sits at the trigger's position.
- The list unfolds from the trigger's edge (`--radix-select-content-transform-origin`, 160 ms) and folds back (120 ms). The exit is possible because the primitive keeps the content mounted while an animation on `[data-state="closed"]` runs. `prefers-reduced-motion` removes both.

## Markup & styling

Block `.platform-select`, a wrapper `<div>` so the trigger and the list share one root, as the CSS convention asks.

**Elements:** `.platform-select__trigger` (`_empty_named` when there is an `emptyOption`), `.platform-select__icon`, `.platform-select__chevron`, `.platform-select__content`, `.platform-select__viewport`, `.platform-select__group`, `.platform-select__group-label`, `.platform-select__item`, `.platform-select__indicator`, `.platform-select__check`

**States (data attributes set by the primitive):** `[data-placeholder]`, `[data-disabled]`, `[data-state="open"]` on the trigger; `[data-state="open"]`/`[data-state="closed"]` on the content, which drive its animations; `[data-highlighted]`, `[data-state="checked"]`, `[data-disabled]` on an item.

**Keyframes:** `platform-select-in`, `platform-select-out`, at the top level because `@keyframes` cannot be nested.

**Tokens:** `--platform-accent`, `--platform-accent-ink`, `--platform-accent-soft` (the accent tone), `--platform-border`, `--platform-selection`, `--platform-selection-soft`, `--platform-shadow-card`, `--platform-surface`, `--platform-text`, `--platform-text-faint`, `--platform-text-muted`, `--platform-text-subtle`

**Breakpoints:** `(prefers-reduced-motion: reduce)` removes the animations.

## Usage

Inside a field:

```tsx
import { PlatformSelect } from "@/components/platform/shared/platform-select/platform-select.comp";

<PlatformFormField name="resultCode" label="Resultado">
  <PlatformSelect
    options={results.map((result) => ({ value: result.code, label: result.label }))}
    defaultValue={results[0]?.code}
    required
  />
</PlatformFormField>;
```
