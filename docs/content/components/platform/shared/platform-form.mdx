## Purpose

The form controls of the platform are built on [Radix Primitives](https://www.radix-ui.com/primitives): unstyled, accessible pieces the project draws with its own BEM stylesheets and `--platform-*` tokens. This is the form itself. `PlatformForm` renders Radix's `Form.Root`, which is a `<form>` for every purpose — `action={serverAction}` posts exactly as before — with one change of behaviour: when the browser finds a field invalid on submit, the primitive swallows the native bubble and the field shows its own message. The browser still blocks the submit, so an `onSubmit` handler only ever runs with a valid form.

`PlatformFormField` is one field: the label, the control and the messages. The control is passed as a single element and receives `id` and `name` from the field (Radix's `Form.Control asChild`), so the label reaches it and the submitted `FormData` carries it under the field's name.

Every form of the platform with fields is on it since 2026-10-08, when the last ones left the native `FormField`, which was deleted: the staff and teacher editors, the account forms and the filters and searches that have a label.

**From a Server Component.** Most of those forms are sections rendered on the server, and they mount `PlatformForm` and `PlatformFormField` as they are, with the control written in the section. While the server renders the HTML, a control that came through the RSC payload can still be a lazy reference to the element, and only the browser gets the element itself: read as it came, its `required` gave «Opcional» in the browser alone (a hydration error) and `PlatformFormGroup`'s `cloneElement` refused it. The field and the group unwrap it first (`useResolvedElement`, the way Radix's own `Slot` does).

## Props

### `PlatformForm`

Everything `<form>` takes. `className` is added to `.platform-form`.

### `PlatformFormField`

| ------------- | ---------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`        | `string`               | yes      | The field's name in the submitted `FormData`. Given to the control; the control must not set its own.                                                                                                                                                                                                                                                                                                                 |
| `label`       | `string`               | yes      | The label text. It targets the control through the `id` the field gives it.                                                                                                                                                                                                                                                                                                                                           |
| `children`    | `ReactElement`         | yes      | The control: a native `input`/`textarea`, or a [`PlatformSelect`](/components/platform/shared/platform-select).                                                                                                                                                                                                                                                                                                       |
| `hint`        | `string`               | no       | Small help text under the control.                                                                                                                                                                                                                                                                                                                                                                                    |
| `info`        | `string`               | no       | A clarification folded into an "i" ([`PlatformInfoTip`](/components/platform/shared/platform-info-tip)), named «Sobre «label»»: for what helps the first time and would be a line of small print every time after. On a text input it sits **inside the control, at its right end**; on a `<textarea>`, in **a strip under the text, inside the same frame**, with the count of its `maxLength`. A select takes none. |
| `messages`    | `PlatformFormMessages` | no       | Text per validity state (`valueMissing`, `tooLong`, `typeMismatch`…), merged over Spanish defaults, which every state has («Este campo es obligatorio.», «Es demasiado alto.» for a number over its `max`…). Only the matching one renders.                                                                                                                                                                           |
| `serverError` | `string`               | no       | A failure the server reported for this field: rendered as its message and the field marked invalid until the user changes the control.                                                                                                                                                                                                                                                                                |

### `PlatformFormGroup`

For a field whose control is a group, not one element: a `<label>` cannot name a radio group, so the label is plain text and the control is pointed at it with `aria-labelledby` (the child is cloned with that prop). Same look as a field. Its messages are two (2026-10-15): `serverError`, drawn as a field's, and `valueMissing`, shown when a required group of cards was submitted with nothing chosen — the group hears the `invalid` event the hidden native control fires, in capture (it does not bubble), swallows the browser's bubble, which would point at a hidden control, and keeps the message until the next change. Both mark the group `data-invalid`.

| Prop           | Type           | Required             | Meaning                                                                                                                                                             |
| -------------- | -------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`        | `string`       | yes                  | The group's name.                                                                                                                                                   |
| `children`     | `ReactElement` | yes                  | The group control: [`PlatformChoiceCards`](/components/platform/shared/platform-choice-cards), a set of checkboxes…                                                 |
| `hint`         | `string`       | no                   | Help text under the group.                                                                                                                                          |
| `optional`     | `boolean`      | no · default `false` | The group may be left with nothing chosen (a set of check cards with no minimum): «Opcional» beside its label. Said here because a group has no `required` to read. |
| `serverError`  | `string`       | no                   | A failure the server reported for this group, as its message.                                                                                                       |
| `valueMissing` | `string`       | no                   | What to say when the group is required and nothing was chosen on submit.                                                                                            |

## Behaviour

- **«Opcional», read from the control** (2026-10-05). A field whose control can be left empty — a `<textarea>`, or an `<input>` one types into (text, email, password, url, tel, number, a date or time) — and has no `required` gets [`OptionalMark`](/components/platform/shared/optional-mark) right after its label: `isOptionalControl(children)`. A search box, a checkbox, a hidden input, a `PlatformSelect` (even with an `emptyOption`) and the choice cards never get it: they are a query, or always show a choice. A required field has no mark at all; the browser and a screen reader already say it. The mark is the label's sibling, outside the name, and `aria-hidden`. It replaced `optionalLabel`, a word each caller wrote at the row's other end, which could say «Opcional» on a required control. Inside [`OptionalFields`](/components/platform/shared/optional-fields) no mark shows.
- **A textarea's "i" lives in a strip** (2026-10-05, option B of four, the owner's choice). With `info` and a `<textarea>`, the field draws `TextareaFrame`: the border moves to `.platform-form__frame`, which holds the textarea, borderless, and under it `.platform-form__strip` — at its left the count of what is written of the textarea's `maxLength` («88 / 1000», read out as «88 de 1000 caracteres»; none without a `maxLength`), at its right the "i". The count follows the typing (`input` on the frame), starts from the saved value (`defaultValue`) and starts again from it when the form resets or a new saved value remounts the textarea. The textarea has no handle and grows with its text (`field-sizing: content`), from three lines to 320px, where it scrolls; a browser without `field-sizing` keeps the handle (`@supports`). A press on the strip's blank part focuses the text, as a press under its last line does. The frame takes the focus ring when the text has the focus — not when the "i" does — and the red of an invalid field. The "i" of an input stays inside it, at its end; a textarea's end is wherever its last line is, which is why it gets the strip.
- Validation is the browser's (`required`, `maxLength`, `type`, `pattern`). The primitive listens to the `invalid` event, prevents the bubble, focuses the first invalid control and marks its field with `data-invalid`; the matching `Form.Message` renders. Changing the control clears it.
- `serverError` uses `serverInvalid` on the field: the message shows at once, the control gets `aria-invalid`, and the first server-invalid control is focused.
- A `PlatformSelect` inside a field submits through the hidden native select the primitive keeps. Give it a `defaultValue` when it is `required`: the hidden select is not a Radix control, so an empty required select would block the submit without a message.

## Markup & styling

Block `.platform-form`, the root being the `<form>`. Native controls are styled as direct children of the field (`.platform-form__field > input`), because Radix's `Control` renders the given element with no wrapper; a select brings its own look from `.platform-select`.

**Elements:** `.platform-form__field`, `.platform-form__label-row`, `.platform-form__label`, `.platform-form__hint`, `.platform-form__message`, `.platform-form__info` (the "i"), `.platform-form__frame` (a textarea with an "i": the border around the text and the strip), `.platform-form__strip`, `.platform-form__count`, `.platform-form__sr` (the count in words, visually hidden)

**The label is light** (2026-10-05): the text size (`md`), regular weight, the muted grey; it was bold, in the text colour and a step larger, and the owner preferred the lighter one. The label row is a wrapping flex line, the label and the mark after it.

**Modifiers:** `.platform-form__field_with_info`. A field with an "i" is a one-column grid where the control and the "i" share the second row, the "i" at its end and centred; the input keeps room for it (`padding-right`, the scale's `space-12`). The "i" is the control's sibling, outside the label, so the label names the input alone.

**States:** `.platform-form__field[data-invalid]` turns the control's border red, and with the focus its ring red too (`--platform-danger`, drawn strong): an invalid field keeps saying so while it is being fixed, instead of taking the selection's blue, which would say all is well (2026-10-06).

**Tokens:** `--platform-border`, `--platform-danger`, `--platform-selection`, `--platform-selection-soft`, `--platform-surface`, `--platform-text`, `--platform-text-muted`, `--platform-text-subtle`

No media queries.

## Usage

From `components/platform/sections/studies/studies-list/new-study.comp.tsx`:

```tsx
import { PlatformForm, PlatformFormField } from "@/components/platform/shared/platform-form/platform-form.comp";
import { PlatformSelect } from "@/components/platform/shared/platform-select/platform-select.comp";

<PlatformForm action={createStudy} onSubmit={() => dialogRef.current?.close()}>
  <PlatformFormField name="name" label="Nombre" messages={{ valueMissing: "Ponle un nombre al estudio." }}>
    <input type="text" maxLength={120} required autoFocus />
  </PlatformFormField>
  <PlatformFormField name="description" label="Descripción">
    <textarea maxLength={500} rows={3} />
  </PlatformFormField>
  <PlatformFormGroup label="Tipo">
    <PlatformChoiceCards name="kindCode" defaultValue={kinds[0]?.code} required options={options} />
  </PlatformFormGroup>
</PlatformForm>;
```
