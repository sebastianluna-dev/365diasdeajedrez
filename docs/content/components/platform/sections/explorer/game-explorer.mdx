## Purpose

Move the pieces and see which games the viewer may see reached that position and how they continued. The search is by **position**, so it also finds games that arrived by another move order.

Since 2026-10-23 it is drawn in the new design system («M4» of the owner's canvas, see [Styling › The new design system](/ui/styling#the-new-design-system-material-3-expressive)), and it draws the whole `.platform-workspace`, because both columns are the board's state:

- **The side column** (`.platform-workspace__side`): «Jugadas», the line played so far ([`ExplorerMoveList`](/components/platform/sections/explorer/explorer-move-list)), and «Buscar en», a [`PlatformSideNav`](/components/platform/shared/platform-side-nav) with the views of `EXPLORER_VIEWS` — «Todas las partidas», «Estudios de alumnos», «Cursos», «Profesorado» — each with how many games of it went through the position on the board (`originCounts`; the first, their sum), the one on screen lit.
- **The panel**: a toolbar on a hairline (`--platform-m3-divider`) with the position's name («Posición inicial», «Después de 5.Cc3», «Después de 5…a6»), who moves («juegan negras») and how many games of the view went through («88 partidas pasaron por aquí»), and «Reiniciar» at its end (`mdButton("text")`); under it the board (`look="material"`, up to 480px) with Material's wide keys under it — the way forward filled, the rest on the container's grey, in Sharp Light, and «Girar el tablero» apart — and at its right the continuations and the games, each an outlined card.

The line lives as a list of SAN and the positions are derived with `replayGame`, the same replayer the rest of the platform uses: the board, the position index and the panels cannot disagree. The search fires with the position already changed, never while a piece is being dragged, because [`ChessBoard`](/components/chess/chess-board) only notifies legal, completed moves.

## Props

| Prop     | Type             | Required | Meaning                                                                                     |
| -------- | ---------------- | -------- | ------------------------------------------------------------------------------------------- |
| `origin` | `GameOriginCode` | no       | The view on screen, from `?origen=` (`explorerOriginOf`); none searches every visible game. |

## Behaviour

- **State:** `sans` (the line), `index` (current ply), `flipped`, `result`, `isSearching`, `hasError`, plus a `Map<string, PositionSearchResult>` cache in a ref, keyed by the view and the FEN.
- **The view lives in the address.** The side column's links go to `/explorador?origen=<alumnos|cursos|profesorado>` (`explorerViewHref`); the page renders again with another `origin` and this component stays mounted — the router keys a page by its segment without the search parameters — so the line, the board's side and the cache survive the change.
- **Search effect (keyed on the current FEN and the view):** a cached result is used immediately; otherwise `searchPosition(fen, { origins: [origin] })` runs with a `cancelled` flag so the response of a position that is no longer current is discarded. A refused answer (`throttled`) is not cached. Going back and forth along the line, the explorer's most common gesture, costs no query. The cache is local because the project has no client data library and one screen does not justify adding one.
- **Playing** a move (from the board or from the continuations card) truncates the line at the current index and appends; the keys and the pills of the line move the index; «Reiniciar» clears the line.
- The board is controlled with the current position and `interactive`; the results dim with `_state_loading` (and say `aria-busy`) while searching but the board stays playable, since waiting to be able to move would be worse than a stale figure for an instant. The toolbar leaves the count out until the answer arrives, and so do the side column's counts and the toolbar after a failed or refused search: «0» would be a false fact about the position.
- A failed search, or one refused by the rate limit, shows a `role="status"` line in `--platform-m3-error` instead of the two cards.

## Markup & styling

Block `.game-explorer` (124 lines), on the same element as `.platform-workspace`, whose `__side` and `__panel` it shares.

**Elements:** `.game-explorer__side`, `.game-explorer__panel`, `.game-explorer__toolbar`, `.game-explorer__position` (the page's `<h1>`), `.game-explorer__summary`, `.game-explorer__reset`, `.game-explorer__body`, `.game-explorer__board`, `.game-explorer__keys`, `.game-explorer__key`, `.game-explorer__flip`, `.game-explorer__results`, `.game-explorer__error`

**Modifiers and states:** `.game-explorer__key_tone_grey` (a key but the way forward: `--container-color` and `--icon-color` of Material's tonal button set to the container and the ink), `.game-explorer__results_state_loading`

**Tokens:** `--platform-m3-container`, `--platform-m3-divider`, `--platform-m3-error`, `--platform-m3-on-surface`, `--platform-m3-on-surface-variant`

**Breakpoints:** `(width < 1280px)` puts the results under the board (one column up to 560px); `(width < 640px)` lets the five keys share the width and fits the toolbar to the panel's smaller padding. Under 1024px the workspace itself puts the side column above the panel.

## Usage

From `components/platform/sections/explorer/game-explorer.section.tsx`:

```tsx
import { GameExplorer } from "./game-explorer.comp";

<GameExplorer origin={origin} />;
```
