## Purpose

Move the pieces and see which games the student may see reached that position and how they continued. The search is by **position**, so it also finds games that arrived by another move order.

The line lives as a list of SAN and the positions are derived with `replayGame`, the same replayer the rest of the platform uses: the board, the position index and the panels cannot disagree. The search fires with the position already changed, never while a piece is being dragged, because [`ChessBoard`](/components/chess/chess-board) only notifies legal, completed moves.

## Props

This component takes no props.

## Behaviour

- **State:** `sans` (the line), `index` (current ply), `flipped`, `result`, `isSearching`, `hasError`, plus a `Map<string, PositionSearchResult>` cache in a ref.
- **Search effect (keyed on the current FEN):** a cached result is used immediately; otherwise `searchPosition(fen)` runs with a `cancelled` flag so the response of a position that is no longer current is discarded, and the result is cached either way. Going back and forth along the line, the explorer's most common gesture, costs no query. The cache is local because the project has no client data library and one screen does not justify adding one.
- **Playing** a move (from the board or from the continuations panel) truncates the line at the current index and appends; navigation buttons move the index; "Reiniciar" clears the line.
- The board is controlled with the current position and `interactive`; the panel dims with `_loading` while searching but the board stays playable, since waiting to be able to move would be worse than a stale figure for an instant.
- A failed search shows a `role="status"` message instead of the two result panels.
