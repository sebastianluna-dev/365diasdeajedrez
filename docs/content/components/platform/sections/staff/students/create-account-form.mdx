## Purpose

There is no public sign-up and no activation email: staff creates the account and hands the password over. When the password field is left empty the action generates a temporary one, and it has to come **back** to be shown once. That rules out the platform's usual redirect-with-`?error=` pattern, because a password in the URL would end up in the history, the Referer and the logs. Hence `useActionState`, the only exception together with [`ResetPasswordForm`](/components/platform/sections/staff/students/reset-password-form).

Known and accepted consequence: this form **needs JavaScript**. Without it the action id is not emitted and the submit does not reach the server. It is an internal panel; the exception is not extended to any other form.

## Props

This component takes no props.

## Behaviour

- `useActionState(createStudentAccount, ACCOUNT_INITIAL_STATE)` yields `{ status, message?, tempPassword? }`, the action and `isPending`.
- `status === "error"` renders a [`PlatformNotice`](/components/platform/shared/platform-notice); `status === "ok"` renders the [`TempPasswordNotice`](/components/platform/sections/staff/students/temp-password-notice) when a password was generated, otherwise a success notice.
- Fields: display name (required), email (required, `autoComplete="off"`), optional initial password as a plain text input (staff is typing it to hand it over, not to hide it). The submit is disabled while pending.
