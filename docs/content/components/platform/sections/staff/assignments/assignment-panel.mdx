## Purpose

Assigning a student to a teacher is one operation seen from two records, so one component serves both pages and shares the same services and actions. Reassigning **closes** the active row and creates another; history is never deleted, and the student's page shows it.

## Props

A discriminated union on `mode`:

| Mode          | Props                                                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"byStudent"` | `studentId: string` · `assignments: StudentAssignmentHistoryItem[]` (full history; the active one has `isActive`) · `teachers: { id, displayName }[]` |
| `"byTeacher"` | `teacherId: string` · `students: TeacherStudentAssignment[]` (active assignments) · `assignable: AssignableStudent[]` (with `currentTeacherName?`)    |

## Behaviour

- **By student:** a line with the current teacher and date (or "no teacher"); a `<form action={assignStudent}>` with hidden `studentId` and `returnTo`, a `teacherId` select and an optional note, labelled "Asignar" or "Reasignar"; when active, a one-button form posting `endAssignment.bind(null, active.id)`; and the history list (teacher, dates, who assigned, note).
- **By teacher:** the list of active students with a "Terminar" form each, and an add form with hidden `teacherId`, a `studentId` select over `assignable` (showing "ahora con …" for students who would be reassigned) and a note.
- `returnTo` tells the action which record to redirect back to.

## Usage

From `components/platform/sections/staff/students/student-admin-detail.section.tsx`:

```tsx

```
