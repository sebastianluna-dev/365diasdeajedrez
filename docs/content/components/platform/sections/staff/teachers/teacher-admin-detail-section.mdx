## Purpose

Four cards: the profile (the same fields the teacher edits in their own profile, plus the login email as a fact), the **status**, the assigned students, and the classes. Deactivating a teacher blocks their panel and new assignments but does **not** close the assignments they hold: reassigning students is a human decision, so the card warns how many assignments will stay open before the button.

## Props

| Prop         | Type                  | Required | Meaning                                                                                                       |
| ------------ | --------------------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| `teacher`    | `StaffTeacherDetail`  | yes      | `id`, `displayName`, `email`, `title?`, `timezone?`, `photo?`, `bio?`, `isActive`, `students[]`, `classes[]`. |
| `assignable` | `AssignableStudent[]` | yes      | Students the teacher could receive, with their current teacher's name if any.                                 |
| `errorCode`  | `string`              | no       | `?error=` translated with `STAFF_ERROR_MESSAGES`.                                                             |

## Behaviour

- Profile: `<form action={updateTeacher.bind(null, id)}>` with display name, title, time zone, photo URL and bio.
- Status: a one-button form posting `setTeacherActive`; a hidden `isActive=on` travels only when reactivating, so an absent field means deactivate. An info [`PlatformNotice`](/components/platform/shared/platform-notice) precedes it when active assignments exist.
- Assignments: [`AssignmentPanel`](/components/platform/sections/staff/assignments/assignment-panel) in `byTeacher` mode.
- Classes: a [`PlatformTable`](/components/platform/shared/platform-table) with title, date, status and participants.

## Usage

