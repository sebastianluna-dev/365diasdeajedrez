## Purpose

A teacher is an account plus a teacher record. Two ways to get there, each its own form so that no field is silently ignored: **link** someone who already has an account (they keep using the platform as a student too), or **create** account and record together. The same action handles both, deciding by whether `userId` was sent.

## Props

| Prop            | Type             | Required | Meaning                                                        |
| --------------- | ---------------- | -------- | -------------------------------------------------------------- |
| `linkableUsers` | `LinkableUser[]` | yes      | Accounts without a teacher record, for the link form's select. |
| `errorCode`     | `string`         | no       | `?error=` translated with `STAFF_ERROR_MESSAGES`.              |

## Behaviour

- Link form: `userId` (select, required), display name (required), title, time zone (default `America/Mexico_City`).
- Create form: display name, email (required), optional initial password (a generated one is handed over by resetting it from the record, where it is shown once), title, time zone, bio.
- Both redirect to the new record on success.
- Both are `PlatformForm`s with a `PlatformFormField` per field (2026-10-08; they were `FormField`s). An input the browser rejects — an empty name or email — shows its own message under it and nothing is sent. The two forms repeat names (`displayName`, `title`, `timezone`) without clashing: each field takes a generated `id`.

## Markup & styling

**Breakpoints:** `(width < 1024px)` stacks the two cards.

## Usage

From `app/(platform)/administracion/profesores/nuevo/page.tsx`:
