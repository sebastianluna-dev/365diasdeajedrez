# `CourseNameFields`

|            |                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------ |
| File       | `components/platform/sections/staff/courses/course-name-fields.comp.tsx`                   |
| Kind       | Client Component                                                                           |
| Stylesheet | `course-name-fields.comp.css` → block `.course-name-fields`                                |
| Used by    | [`CourseEditorSection`](/components/platform/sections/staff/courses/course-editor-section) |
| Composes   | [`PlatformFormField`](/components/platform/shared/platform-form) (the slug's with `info`)  |
| Uses       | `slugAfterRename` from `lib/generate-slug`                                                 |

## Purpose

The one piece of the course's metadata form that needs state, split out so the rest of the editor stays on the server. It renders the «Nombre» and «Slug» fields inside the form that holds it, the editor's [`PlatformForm`](/components/platform/shared/platform-form); it has no form nor action of its own, and it cannot be mounted outside one: a `PlatformFormField` needs its form's context.

## Props

| Prop   | Type     | Required | Meaning                  |
| ------ | -------- | -------- | ------------------------ |
| `name` | `string` | yes      | The course's saved name. |
| `slug` | `string` | yes      | The course's saved slug. |

## Behaviour

- **The slug follows the name.** When the name loses focus **having changed**, the slug becomes `generateSlug(name)`, whatever it was before, a slug typed by hand included.
- Leaving the name as it was touches nothing, so tabbing through the field does not undo a slug of one's own.
- A name that yields no slug («¡¿?!», or empty) leaves the slug alone: a rename never empties the field.
- **What the slug is goes in an "i"** inside its input, at the right end — [`PlatformFormField`](/components/platform/shared/platform-form)'s `info`, a [`PlatformInfoTip`](/components/platform/shared/platform-info-tip) — with «Se actualiza al cambiar el nombre; puedes ajustarlo después. Minúsculas, números y guiones.», instead of a hint under the field. The format is enforced by the input's `pattern`: a slug it rejects is answered under the field with «Minúsculas, números y guiones.» (the field's `patternMismatch` message, in the words of the input's `title`), an empty one with «Este campo es obligatorio.».
- Both are `PlatformFormField`s, the slug with `info`: the "i" sits outside the label, so the input's name is «Slug» alone.
- The slug stays editable; what is typed there holds until the next rename.
- Nothing is saved until «Guardar metadatos»: a slug already taken is answered by `updateCourse` with «Ese identificador (slug) ya está en uso.».
- Unlike [`NewCourseForm`](/components/platform/sections/staff/courses/new-course), where a slug typed by hand is left alone, here the name always rules: the rule is `slugAfterRename(previousName, nextName, currentSlug)` in `lib/generate-slug.ts`, tested there.
- Both inputs are uncontrolled (`defaultValue`), like the rest of the form; the only thing kept is a ref with the name the field had when it took focus.

## Markup & styling

Block `.course-name-fields` (5 lines), with `display: contents` and nothing else: the two fields stay direct items of the form's column, spaced by its gap like any other. Where the "i" goes is `PlatformFormField`'s.

No tokens, no media queries.

## Usage

From `components/platform/sections/staff/courses/course-editor.section.tsx`:

```tsx
import { CourseNameFields } from "./course-name-fields.comp";

<PlatformForm action={updateCourse.bind(null, course.id)}>
  <CourseNameFields name={course.name} slug={course.slug} />
  {/* description, content types, levels… */}
</PlatformForm>;
```
