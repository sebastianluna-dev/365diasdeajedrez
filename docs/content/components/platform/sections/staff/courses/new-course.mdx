## Purpose

Creating a course is three fields, so it lives in a modal on the catalog page rather than on a page of its own (`/administracion/cursos/nuevo` no longer exists). The modal is a [`PlatformPopup`](/components/platform/shared/platform-popup), the one popup of the platform: the strip with the name and the cross, the focus trap, Escape and the backdrop come with it. `NewCourse` is the button and the popup; `NewCourseForm` is the form, split off so the story can mount it with a stub in place of the server action. It is the staff twin of [`NewStudy`](/components/platform/sections/studies/studies-list/new-study).

| -------------- | --------------------- | -------- | ---------------------------------------------------------------------------------------------- |
| `contentTypes` | `ContentTypeOption[]` | yes      | The content types on offer, from `listContentTypes()`, drawn as cards with their descriptions. |

## Behaviour

- **The trigger** is the platform's button (`.platform-button`), the same one every action of the staff's courses uses; it opens the popup with `open(event)`.
- The form is a `PlatformForm` with `action={createCourse}` and `autoComplete="off"`: the subtitle «Sólo lo imprescindible: el resto se edita en la ficha del curso.» as its first line, `name` (required, max 160, controlled so the submit can watch it; the first control, so the popup opens on it), `slug` (required, max 160, `pattern` of lowercase words joined by single hyphens, with its own `patternMismatch` text, controlled too) and `contentTypeCodes`, a `PlatformCheckCards` over `contentTypes` inside a `PlatformFormGroup` whose label carries the rule («Contenido», with no «Opcional» beside it: that is what says one is required), nothing chosen at first. A footer band says the course is born in draft and carries the buttons.
- **The slug writes itself.** When the name loses focus, the slug takes `generateSlug(name)` (the same helper the CMS uses: lowercase, accents stripped, words joined by single hyphens), as long as the slug is still the form's and not the user's. Once they type a slug of their own it is left alone whatever the name does; clearing it hands it back to the name. The field's hint says so.
- **Crear curso** stays disabled until the name and the slug have a character that is not a space and at least one content type is chosen: the browser cannot demand "one of these boxes", so the form does, and the action's `formCodeList(…, 1)` does it again on the server (`contentTypeRequired`).
- The popup is `PlatformPopup` at `lg` (720px, wider than the study's so the eight content-type cards sit in three columns), named «Nuevo curso» by its strip; the trigger opens it with `open(event)`, so the focus returns to the button on closing. Its motion and its frame are the popup's: this stylesheet draws nothing of the shell.
- Every closing remounts the form (`key` bumped in the popup's `onClose`), so it never opens with what was typed the last time. On closing and not on opening: `open()` focuses the form it finds, and one remounted in the same click would take that focus with it.
- «Cancelar» and `onSubmit` close the popup. The browser validates `required` and `pattern` before the submit event fires (the form primitive only replaces the bubble with the field's message), so the popup does not close with a bad form.
- The action creates the course in draft and redirects to its editor. A failure it can only see on the server (a slug already in use, the rate limit) comes back to the catalog as `?error=<code>`, which [`CoursesAdminSection`](/components/platform/sections/staff/courses/courses-admin-section) renders as a `PlatformNotice` under the header.

## Markup & styling

Block `.new-course`: the body's padding and spacing (24px, to the strip's edge), the subtitle and the footer band. The shell (frame, strip, cross, width) is `PlatformPopup`'s; the fields' and controls' look come from `.platform-form` and `.platform-check-cards`.

**Elements:** `.new-course__form`, `.new-course__body`, `.new-course__subtitle`, `.new-course__foot`, `.new-course__note`, `.new-course__actions`

**Other classes it renders:** `.platform-popup` (with `.platform-dialog`, the shared frame in `platform.css`), `.platform-button` (the trigger, «Cancelar» and «Crear curso»), `.platform-form`, `.platform-check-cards`.

**Tokens:** `--platform-bg`, `--platform-border`, `--platform-text-muted`

**Breakpoints:** none of its own. The popup handles narrow screens and reduced motion.

## Usage

From `CoursesAdminSection`:

```tsx
import { NewCourse } from "@/components/platform/sections/staff/courses/new-course/new-course.comp";

<NewCourse contentTypes={contentTypes} />;
```
