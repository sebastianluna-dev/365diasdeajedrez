## Purpose

Chapters in a course and lessons in a chapter are the same row with different content, so one list serves both. In a five-chapter course the arrow buttons were enough, but moving the fifth to the first place was four round trips to the server; dragging does it in one.

The order is applied on the client on drop and saved in a transition without waiting for a response: reordering is where a flicker shows most, and the list already knows how it will end up. If the server rejects the change, its revalidation returns the good order and the row goes back.

## Props

| Prop | Type | Required | Meaning |
| --- | --- | --- | --- |
| `items` | `SortableItem[]` | yes | `{ id, name, meta, href, badge?, roleLabel?, canDelete }[]`. `roleLabel` ("Introducción", "Cierre") marks a fixed row. |
| `onReorder` | `(orderedIds: string[]) => Promise<void>` | yes | Server action already bound to its course or chapter; receives the ids of the **normal** rows only. |
| `deleteAction` | `(formData: FormData) => Promise<void>` | no | Delete action; rendered per row when `canDelete`. |
| `deleteFieldName` | `string` | no | The hidden field the delete action reads (`chapterId`, `lessonId`). |
| `noun` | `string` | yes | What an item is called, for the handle's `aria-label`. |
| `emptyLabel` | `string` | yes | Text when there are no rows. |

## Behaviour

- **Fixed rows.** Intro and closing travel in the same list so they are seen where they belong, but they are not draggable, cannot be dropped onto, and are left out of the ids sent; the server would not accept them either. The displayed number counts only normal rows, so with an intro in front the first real chapter is 1, not 2.
- **Drag.** Normal rows are `draggable`; `onDragOver` prevents default so the row is a valid drop target; `onDrop` moves the dragged index and commits.
- **Keyboard.** The handle is a `<button>` with an `aria-label` naming the item and explaining the arrows; ArrowUp and ArrowDown move the row one step. Dragging has no keyboard equivalent, so this is the only accessible way to reorder.
- **Sync with the server.** New `items` after revalidation replace the local rows **during render** (via a `baseline` comparison), not in an effect, avoiding a frame with the old list.
- Each row shows a link to edit, the badge, the meta line, and a delete form when allowed.

## Usage

From `components/platform/sections/staff/courses/chapter-editor.section.tsx`:

```tsx
import { SortableList } from "./sortable-list.comp";

<SortableList
  items={chapter.lessons.map((lesson) => ({
    id: lesson.id,
    name: lesson.name,
    meta: `${lesson.hasPgn ? "Con PGN" : "Sin PGN"} · ${lesson.exerciseCount} ejercicio${lesson.exerciseCount === 1 ? "" : "s"}`,
    href: lesson.href,
    roleLabel: lesson.roleLabel,
    badge: lesson.isPriority ? "Prioritaria" : undefined,
    canDelete: isDraft && lesson.progressCount === 0,
  }))}
  onReorder={reorderLessons.bind(null, chapter.courseId, chapter.id)}
  deleteAction={deleteLesson.bind(null, chapter.courseId, chapter.id)}
  deleteFieldName="lessonId"
  noun="lección"
  emptyLabel="Este capítulo todavía no tiene lecciones."
/>
```
