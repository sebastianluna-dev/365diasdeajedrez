## Purpose

Editing a course as **independent cards**, each with its own form and action, instead of one giant form where a failure in one field throws away all the work. Left column, what is written and ordered: metadata and chapters. Right column, what is glanced at: cover, authors and status, touched once and looked at many times.

## Props

| Prop                             | Type                | Required | Meaning                                                                                                                                                                                                                |
| -------------------------------- | ------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `course`                         | `CourseAdminDetail` | yes      | `id`, `name`, `slug`, `description?`, `cover?`, `typeCode`, `levelCodes`, `statusCode`, `statusLabel`, `publishedAtLabel?`, `canPublish`, `chapters[]` (with `roleCode`, `lessonCount`, `progressCount`), `authors[]`. |
| `types`, `levels`, `authorRoles` | `CatalogOption[]`   | yes      | Catalog options for the selects and checkboxes.                                                                                                                                                                        |
| `authors`                        | `AuthorAdminRow[]`  | yes      | All authors; those already on the course are filtered out of the add select.                                                                                                                                           |
| `gameCount`                      | `number`            | yes      | For the "Partidas" tab count; the list lives in its own tab.                                                                                                                                                           |
| `errorCode`                      | `string`            | no       | `?error=` translated with `STAFF_ERROR_MESSAGES`.                                                                                                                                                                      |

## Behaviour

- **Metadata** form (`id="course-metadata"`): name, slug (pattern-checked), type, description, levels as a [`FormFieldset`](/components/platform/shared/form-field). The cover lives in the aside but belongs to this form through [`ImageUpload`](/components/platform/shared/image-upload)'s `form` prop, so it saves with "Guardar metadatos".
- **Chapters:** a [`SortableList`](/components/platform/sections/staff/courses/sortable-list) with drag and keyboard reordering (`reorderChapters`), delete offered only where the server allows it (draft course, no student progress), an inline "Añadir capítulo" form, and "Añadir introducción" / "Añadir cierre" buttons that vanish once each role exists (the database's unique index is the real guarantee).
- **Authors:** ordered rows with up, down and remove forms (`manageCourseAuthors` with an `operation` field) and an add form with author and role.
- **Estado:** facts, an info notice when `canPublish` is false (needs a chapter with a lesson that has a game), and the publish (disabled until allowed) and archive forms. A published course gets a "Ver en la plataforma" link in the head.

## Usage

From `app/(platform)/administracion/cursos/[courseId]/page.tsx`:

```tsx
import { CourseEditorSection } from "@/components/platform/sections/staff/courses/course-editor.section";

<CourseEditorSection
  course={course}
  types={types}
  levels={levels}
  authors={authors}
  authorRoles={authorRoles}
  gameCount={gameCount}
  errorCode={error}
/>;
```
