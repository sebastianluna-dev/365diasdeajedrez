# `SyllabusList`

Also exports the `SyllabusItem` type.

|            |                                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| File       | `components/platform/sections/staff/courses/syllabus-list/syllabus-list.comp.tsx`                       |
| Kind       | Client Component                                                                                       |
| Stylesheet | `syllabus-list.comp.css` → block `.syllabus-list`                                                       |
| Used by    | [`CourseSyllabus`](/components/platform/sections/staff/courses/course-syllabus) (the chapters of a course), [`ChapterEditorSection`](/components/platform/sections/staff/courses/chapter-editor-section) (the lessons of a chapter) |
| Uses       | `useSortableRows` · `use-sortable-rows.hook.ts`                                                         |

## Purpose

**The path the student walks**, top to bottom along a rail: the introduction opens it and the closing ends it, each in its fixed place — a dashed slot while it does not exist —; between them, the numbered items and the field that adds another one.

A course's chapters and a chapter's lessons are the same thing one level apart, so they are one component. Until this, the chapters had the rail and the lessons a row with a drag handle, plus two loose buttons at the foot for the introduction and the closing: the panel of a chapter read as another product from the panel of a course.

The order is applied on the client on drop and saved in a transition without waiting for a response: reordering is where a flicker shows most, and the list already knows how it will end up. If the server rejects the change, its revalidation returns the good order and the row goes back (`useSortableRows`).

## Props

| Prop              | Type                                      | Required | Meaning                                                                                                              |
| ----------------- | ----------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `items`           | `SyllabusItem[]`                          | yes      | `{ id, name, facts, href, roleCode?, badge?, canDelete }[]`. `roleCode` (the introduction's or the closing's) marks a fixed item. |
| `noun`            | `string`                                  | yes      | What one item is called, for the handle's `aria-label`: "capítulo", "lección".                                       |
| `onReorder`       | `(orderedIds: string[]) => Promise<void>` | yes      | Server action already bound to its course or chapter; receives the ids of the **normal** items only.                 |
| `createAction`    | `(formData: FormData) => Promise<void>`   | yes      | Creates one: it reads `name`, and `role` for the introduction and the closing.                                       |
| `deleteAction`    | `(formData: FormData) => Promise<void>`   | no       | Delete action; rendered per item when `canDelete`.                                                                   |
| `deleteFieldName` | `string`                                  | yes      | The hidden field the delete action reads (`chapterId`, `lessonId`).                                                  |
| `newPlaceholder`  | `string`                                  | yes      | What the field at the foot says while it is empty.                                                                   |

## Behaviour

- **Fixed items.** The introduction and the closing travel in the same list so they are seen where they belong, but they are not draggable, cannot be dropped onto, and are left out of the ids sent; the server would not accept them either. The displayed number counts only normal items, so with an introduction in front the first real chapter is 1, not 2.
- **The node is the handle.** An item is dragged by its numbered node, and ArrowUp and ArrowDown move it one step: dragging has no keyboard equivalent, so that is the only accessible way to reorder. The `aria-label` names the item and says so.
- **Creating is part of the list.** The field at the foot adds a normal item; the dashed slots add the introduction and the closing, with their `role` in a hidden field. Both are the same `createAction`, and both are gone from view once what they create exists.
- **Sync with the server.** New `items` after revalidation replace the local rows **during render** (via a `baseline` comparison), not in an effect, avoiding a frame with the old list.
- Each item shows its name (a link), its facts, its badge if it has one, and the platform's row actions: «Editar» and, where the server would allow it, «Eliminar».

## Markup & styling

Block `.syllabus-list`. A column of steps joined by a rail drawn behind the nodes; each step is the node, the text and the actions.

**Elements:** `.syllabus-list__step`, `.syllabus-list__node`, `.syllabus-list__text`, `.syllabus-list__name`, `.syllabus-list__facts`, `.syllabus-list__badge`, `.syllabus-list__actions`, `.syllabus-list__slot`, `.syllabus-list__add`, `.syllabus-list__new`, `.syllabus-list__new-input`, `.syllabus-list__new-submit`

**Modifiers and states:** `.syllabus-list__step_state_dragging`, `.syllabus-list__node_kind_item` (the numbered one, which is the handle), `_kind_intro`, `_kind_closing`, `_kind_new`

**Other classes it renders:** `.platform-row-action` and `.platform-row-action_variant_danger` — «Editar» and «Eliminar» are the platform's row actions, written as words at the end of the row they belong to (see [Styling](/ui/styling)).

## Usage

From `course-syllabus.comp.tsx` (the chapters) and `chapter-editor.section.tsx` (the lessons):

```tsx
<SyllabusList
  noun="lección"
  items={chapter.lessons.map((lesson) => ({
    id: lesson.id,
    name: lesson.name,
    facts: `${lesson.hasPgn ? "Con PGN" : "Sin PGN"} · ${lesson.exerciseCount} ejercicios`,
    href: lesson.href,
    roleCode: lesson.roleCode,
    badge: lesson.isPriority ? "Prioridad" : undefined,
    canDelete: isDraft && lesson.progressCount === 0,
  }))}
  onReorder={reorderLessons.bind(null, chapter.courseId, chapter.id)}
  createAction={createLesson.bind(null, chapter.courseId, chapter.id)}
  deleteAction={deleteLesson.bind(null, chapter.courseId, chapter.id)}
  deleteFieldName="lessonId"
  newPlaceholder="Nombre de la nueva lección…"
/>
```
