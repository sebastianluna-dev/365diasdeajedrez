## Purpose

Marking a student as present records their activity (and with it their statistics) through the only write point that exists for that. The form is therefore submitted **whole**: every participant's checkbox travels and the server diffs against what is stored, so a single action handles ticking and unticking.

## Props

| Prop           | Type                        | Required | Meaning                                                                                          |
| -------------- | --------------------------- | -------- | ------------------------------------------------------------------------------------------------ |
| `classId`      | `string`                    | yes      | Bound into both actions.                                                                         |
| `participants` | `TeacherClassParticipant[]` | yes      | `{ userId, displayName, attended, hasPayment }[]`. Empty renders a hint to enrol students first. |

## Behaviour

- `<form action={markAttendance.bind(null, classId)}>` with `name="attended" value={userId}` checkboxes and a "Guardar asistencia" submit.
- Each row shows "Pago registrado" or "Sin pago registrado".
- "Quitar" is a submit button with `formAction={removeParticipant.bind(null, classId)}` and `name="studentId"`, rendered only for a participant who left no trace (no attendance, no payment); the server rejects the others anyway.
