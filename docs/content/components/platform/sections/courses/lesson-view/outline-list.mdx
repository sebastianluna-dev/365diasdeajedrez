# `OutlineList`

|            |                                                                                              |
| ---------- | ---------------------------------------------------------------------------------------------- |
| File       | `components/platform/sections/courses/lesson-view/outline-list.comp.tsx`                     |
| Kind       | Client Component                                                                             |
| Stylesheet | none of its own: it draws `.lesson-outline__list` and its rows (see [`LessonOutline`](/components/platform/sections/courses/lesson-view/lesson-outline)) |
| Used by    | [`LessonOutline`](/components/platform/sections/courses/lesson-view/lesson-outline)          |

## Purpose

The rows of the column, and the only client piece of it.

Client because of one thing: **which lesson is open**. The column lives in the chapter's layout, and a layout is not rendered again when one moves within it — that is the whole point, the list is not fetched between lessons — so the server cannot mark the row. `usePathname` does, and it does it the instant the link is followed, before the lesson's own PGN has arrived: the row lights up first and the board follows.

Keeping the place in the list is no longer anyone's job either. The element is never unmounted, so its scroll stays where it was; what used to remember it in `sessionStorage` (`OutlineScroll`) went away with the move.

## Props

| Prop      | Type              | Required | Meaning                                    |
| --------- | ----------------- | -------- | -------------------------------------------- |
| `lessons` | `LessonSibling[]` | yes      | The chapter's lessons, in reading order.   |

## Behaviour

- The row whose `href` is the current pathname is not a link — it leads where one already is — and carries `aria-current="page"`, which is what says so to a screen reader and what the stylesheet paints in the accent.
- **It brings the lesson being read back into view when it is cut off**, smoothly, on every change of pathname: above the fold it goes to the top of the list — **under the chapter, not under the top edge**, since the chapter's name is stuck there and what it covers is not room to be seen from (it is found by `[data-sticky-head]` and measured); below the fold, far enough to leave a row's height under it, so it lands as the next to last one in view rather than pressed against the edge. A rect carries the platform's zoom and `scrollTop` does not, so the distances cross over with `currentCSSZoom`. Under `prefers-reduced-motion` the scroll is instant.
- It reaches the scroller through its own `parentElement`, which is the `.lesson-outline__body` it is mounted in, so nothing has to hand it a ref and the column around it stays a Server Component.
