## Purpose

Renders the navigation groups the shell composed on the server and marks the current one. It is a Client Component only because knowing the current path needs `usePathname`; the groups themselves are decided by role on the server and arrive as data.

## Props

| Prop     | Type                 | Required | Meaning                                                                                                                                                                                                                                                                       |
| -------- | -------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `groups` | `PlatformNavGroup[]` | yes      | `{ label?, items: PlatformNavEntry[] }[]`, composed by role and switches in the shell; an entry is a link (`{ label, href }`) or a dropdown (`{ label, items }`, drawn with [`PlatformNavMenu`](/components/platform/shared/platform-nav-menu)). Here they are only rendered. |

## Behaviour

- **Each entry can carry a drawing** (2026-10-18): `art` on an item or a dropdown in `nav-items.const.ts` names it, and [`NavArt`](/components/platform/shared/platform-nav-menu) draws it at 28px before the name — the pawn on a 3×3 board for «Jugar», the puzzle piece for «Ejercicios», the mortarboard for «Aprender», the toolbox for «Herramientas». They are illustrations with their own colours, not icons, and `aria-hidden`; the staff's menu has none. (A side bar with these drawings was tried the same day and taken back: the menu stays the top bar.)
- `activeNavHref(groups, pathname)` returns the item whose `href` is the **longest prefix** of the current path, so `/profesor` and `/profesor/alumnos` do not both appear active on the students page. The active link gets the `_active` modifier and `aria-current="page"`.
- **«Jugar» and «Herramientas»** (2026-10-08, planning decision §H): `buildPlatformNavGroups(roles, features)` puts «Jugar» in the student's bar while `PLAY_ENABLED` is on (never in the teacher's, since 2026-10-19), and gathers the analysis board, the explorer and (with `MOVE_TRAINER_ENABLED`) the trainer into the «Herramientas» dropdown once `ANALYSIS_BOARD_ENABLED` is on; until then the explorer stays a link of its own. The teacher's «Mi perfil» is «Mi ficha», because «Mi perfil» is everyone's profile now. `activeNavHref` looks inside a dropdown too, and its trigger lights up with its tool.
- **The student's bar** (2026-10-18): «Jugar» (with `PLAY_ENABLED`), the «Ejercicios» dropdown («Ejercicios» `/ejercicios`, «Ejercicios por tema» `/ejercicios/temas`, «Puzzle Rush» `/puzzle-rush`), the «Aprender» dropdown («Cursos» `/cursos`, «Estudiar» `/estudios`, «Clases» `/clases`) and «Herramientas» (or the explorer's own link while it is off). «Inicio» is the logo's. The staff's bar is as below.
- **The teacher's bar** (2026-10-19): the «Enseñar» dropdown («Panel del profesor» `/profesor`, «Clases que imparto» `/profesor/clases`, «Calendario» `/profesor/calendario`, «Mis alumnos» `/profesor/alumnos`, «Mi ficha» `/profesor/perfil`), the «Material» dropdown («Ejercicios» `/profesor/ejercicios` with its switch, «Clases prediseñadas» `/profesor/biblioteca-de-clases`), the «Aprender» dropdown («Cursos» `/cursos`, «Estudiar» `/estudios`, which light up for the teacher too) and «Herramientas» (or the explorer's own link while it is off). No «Jugar»: the owner's choice; `/jugar` is still theirs as a user.
- **«Ejercicios»** (`EXERCISES_ENABLED`; `features.exercises` is `"all"`, `"withTeacher"` or `false`): the teacher's bank in «Material» whenever it is on, and the student's dropdown before «Aprender» — for every student with `"all"` (from phase 4, the library), or, with `"withTeacher"` (phases 1–3), only for one who has something there, an active teacher or a series given to them (`roles.hasExerciseSource`, which the shell asks `getStudentExerciseAccess()` for only when `needsStudentExerciseAccess(roles)` says the menu depends on it).
- The group label (`group.label`) is not rendered in the top bar: there is no row to put it on and it would repeat what the first item says ("Administración", "Panel del profesor"). Since the menu is exclusive by role there are never two groups to tell apart.
- `<nav aria-label="Navegación principal">`.

## Markup & styling

Block `.platform-nav` (60 lines).

**Elements:** `.platform-nav__group`, `.platform-nav__item`

**Modifiers and states:** `.platform-nav__item_active`

**Tokens:** `--platform-accent-ink`, `--platform-accent-soft`, `--platform-bg`, `--platform-text`, `--platform-text-muted`

**Breakpoints:** `(width < 1280px)` the menu takes a row of its own under the wordmark and scrolls sideways if it does not fit. In one row it takes what the wordmark and the tools leave, and scrolls sideways inside that.

It sits next to the wordmark, at the left of the bar; what is pushed to the right edge is the shell's user block.

## Usage

From `components/platform/sections/shell/platform-shell.section.tsx`:

```tsx
import { PlatformNav } from "./platform-nav.comp";

const hasExerciseSource = user && needsStudentExerciseAccess(roles) ? await getStudentExerciseAccess() : false;
const navGroups = buildPlatformNavGroups({ ...roles, hasExerciseSource });
// …
<PlatformNav groups={navGroups} />;
```
