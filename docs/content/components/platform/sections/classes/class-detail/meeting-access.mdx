## Purpose

The meeting link must not be readable before the teacher's visibility instant. It therefore **never reaches the client ahead of time**: the service omits `meetingUrl` until the instant has passed, and this component only renders a countdown from `meetingVisibleFromIso`. When the countdown reaches zero it calls `router.refresh()` once, the page re-renders on the server, and the URL arrives as a prop. There is no client-side check that could be bypassed.

## Props

| Prop                    | Type     | Required | Meaning                                                               |
| ----------------------- | -------- | -------- | --------------------------------------------------------------------- |
| `meetingUrl`            | `string` | no       | Present only when the server has already authorised showing the link. |
| `meetingVisibleFromIso` | `string` | no       | ISO instant when the link becomes visible, for the countdown.         |
| `providerLabel`         | `string` | no       | Appended to the button text, "Entrar a la clase (Zoom)".              |

## Behaviour

- With `meetingUrl`: an external link styled as the primary button.
- Without it but with `meetingVisibleFromIso`: an interval ticks every second and `formatRemaining` renders days/hours/minutes or minutes/seconds. The first render shows "…" until the effect runs, avoiding a hydration mismatch on the number.
- At zero the interval stops and `router.refresh()` fires **once**. The page normally comes back with the link, which takes `meetingVisibleFromIso` away and with it the effect's timers. A page that comes back still without it means the browser's clock is ahead of the server's; the prop is unchanged, so the effect keeps its schedule and refreshes again after 1 s, 2 s, 5 s, 10 s and then every 30 s (`meetingRefreshDelay` in `meeting-refresh.ts`, with its test) until the server's clock reaches the instant. It never refreshes every second: at the cap a link that is already there waits at most half a minute. A teacher who moves the instant changes the prop, and the countdown starts over towards the new one.
- With neither: "El enlace de la videollamada aún no está disponible." That is what a class without a link shows: the service sends `meetingVisibleFromIso` only along with a link that is not visible yet, never for a class without one (whatever instant its row stores) and never once the instant has passed.

## Usage

From `components/platform/sections/classes/class-detail/class-detail.section.tsx`:

```tsx
import { MeetingAccess } from "./meeting-access.comp";

{
  isUpcoming && (
    <MeetingAccess
      meetingUrl={classDetail.meetingUrl}
      meetingVisibleFromIso={classDetail.meetingVisibleFromIso}
      providerLabel={classDetail.meetingProviderLabel}
    />
  );
}
```
