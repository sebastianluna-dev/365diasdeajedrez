## Purpose

The list of a study's games: number, name (linked to the game view), white, black, result. In a writable study the rows can be reordered by dragging them by their number or, for keyboard users, with the arrow keys on that same handle; the order is what the study's "chapters" mean.

It is a real `<table>` through the shared [`PlatformTable`](/components/platform/shared/platform-table): the rows are `PlatformTableRow` elements carrying the drag handlers and the dragging class, so the look of a listing is defined once and this file only adds what a study's row needs (the handle, the "En clase" mark).

## Props

| Prop         | Type              | Required | Meaning                                                                                |
| ------------ | ----------------- | -------- | -------------------------------------------------------------------------------------- |
| `studyId`    | `string`          | yes      | Bound into the reorder action.                                                         |
| `games`      | `StudyGameItem[]` | yes      | `{ id, label, href, white, black, resultLabel, citedInClass }[]` in the saved order.   |
| `canReorder` | `boolean`         | yes      | Course databases are read-only: nothing is dragged there and the number is plain text. |

## Behaviour

- **Local order with server sync.** `items` mirrors `games`; when the server revalidates and new props arrive, the state is realigned **during render** (comparing against a `baseline`), not in an effect, so there is no frame painting the old list before correcting it.
- **Drag.** Rows are `draggable` when allowed; `onDragOver` calls `preventDefault` (otherwise the browser refuses the drop) and `onDrop` moves the dragged index to the target. The row being dragged gets `_state_dragging`.
- **Keyboard.** The handle is a `<button>` with an `aria-label` explaining the arrows; ArrowUp/ArrowDown move the row one step.
- **Commit.** Every move updates the state and calls `reorderStudyGames(studyId, ids)` inside a transition; the server persists and revalidates.
- A note under the table explains what can be done and that cited games are marked.

## Markup & styling

Block `.game-table` (about 90 lines); the table, header and cells are `.platform-table__*`.

**Elements:** `.game-table__row` (mixed onto `.platform-table__row`), `.game-table__handle`, `.game-table__number`, `.game-table__grip`, `.game-table__name`, `.game-table__link`, `.game-table__cited`, `.game-table__result`, `.game-table__note`

**Modifiers and states:** `.game-table__row_state_dragging`

**Tokens:** `--platform-accent`, `--platform-accent-ink`, `--platform-accent-soft`, `--platform-text`, `--platform-text-faint`, `--platform-text-subtle`

No media queries of its own: under `minWidth` (560 px) the shared wrapper scrolls horizontally.

## Usage

From `components/platform/sections/studies/study-detail/study-detail.section.tsx`:

```tsx
import { GameTable } from "./game-table.comp";

<GameTable studyId={study.id} games={study.games} canReorder={canWrite} />;
```
