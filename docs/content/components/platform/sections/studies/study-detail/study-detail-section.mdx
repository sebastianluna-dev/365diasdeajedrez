## Purpose

A study is read on its game page: `/estudios/[studyId]` redirects to the first game, and the game page's aside ([`GameAside`](/components/platform/sections/studies/game-view/game-aside)) carries the study's name, actions and games. This section only ever renders when there is no game to go to. The header names the study and says what it is; the action bar offers what the viewer may do, which for its owner is how the study gets its first game; the body is the empty state. What is offered comes from `services/studies/study-rules`, the same table the server actions apply: this section only decides what is **shown**, never what is allowed.

## Props

| Prop         | Type                | Required | Meaning                                                                                                                |
| ------------ | ------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `study`      | `StudyDetail`       | yes      | The study, with `games` empty, `gameCount`, `shares`, `permissions`, `kindCode`, `citedGameCount` and labels.          |
| `kinds`      | `StudyKindOption[]` | yes      | Kinds the student can set when editing. Empty in course databases.                                                     |
| `results`    | `StudyKindOption[]` | yes      | The results catalog, for the blank-game form.                                                                          |
| `classGames` | `ClassGameItem[]`   | yes      | Games seen in class that can be copied. Empty hides that tab of `NewGame`.                                             |
| `students`   | `StudentOption[]`   | yes      | Students to hand a collection to, for a teacher's own collection.                                                      |
| `errorCode`  | `string`            | no       | `?error=` from a bounced action; translated by `STUDY_ERROR_MESSAGES` (`confirmStudyDelete`, `fen`, the common codes). |

## Behaviour

- `canWrite = permissions.canEditGames` gates the whole action bar; inside it `canDelete` gates the delete button ("Mis partidas" is editable but not deletable).
- `canShare` is true only for a **collection** (`DATABASE_KIND.COLLECTION`) the viewer can delete, which means its owner; whoever receives one gets `shares` empty and fails this test too.
- Tags: kind, course name or "Te la compartió …", and "Sólo lectura" when not writable.
- The empty state has different copy for writable and read-only studies.
- Errors render through [`PlatformNotice`](/components/platform/shared/platform-notice) with a fallback message for unknown codes.

## Usage

From `app/(platform)/estudios/[studyId]/page.tsx`, after the redirect to the first game has not happened:

```tsx
import { StudyDetailSection } from "@/components/platform/sections/studies/study-detail/study-detail.section";

<StudyDetailSection
  study={study}
  kinds={kinds}
  results={results}
  classGames={classGames}
  students={students}
  errorCode={error}
/>;
```
