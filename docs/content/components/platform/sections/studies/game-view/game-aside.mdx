## Purpose

A study has no page of its own — its URL redirects to the first game — so this column is where the study lives. The first card is the study: its name and its total head it, its owner's "Editar datos" and "Borrar" sit under them, and its games follow, to jump between them without going back; the owner drags a row (or moves it with the keyboard) to reorder, and "Nueva partida" closes the card. The second card is the game's record, read top to bottom: where it was played, when and how it ended, and at the foot where the game came from and, for the owner, the delete control. The moves are edited on the board itself, so nothing else is left here. A collection's owner gets a third card, the sharing panel.

## Behaviour

- Sibling rows show the student's title or the mapper's `label` fallback (round, event or position in the study), the players as a second line with a `title` tooltip because long names are cut, and the result.
- **Reordering.** The list is local state while a row is dragged; on drop, or on an arrow key on the row's grip, the whole order goes to `reorderStudyGames(studyId, ids)` in a transition. New `siblings` from the server replace the state during render, not in an effect, so the old list is never painted first. The grip is a `<button>` with an `aria-label` so keyboard users move rows too; it only shows on hover or focus. `dragstart` sets its own data so the browser drags the row and not the link's URL.
- **Pages.** With `pages`, a "← Anteriores · Página n de m · Siguientes →" nav sits between the list and "Nueva partida"; the links carry `?pagina=` on the current game's URL.
- `metaCells` always yields **four** cells (Fecha, Ronda, ECO, Resultado) with a dash where there is no value: in a two-by-two grid, hiding one cell displaces the other three, and an incomplete record reads worse than one with declared gaps.
- With `game.canEdit`, [`DeleteGame`](/components/platform/sections/studies/game-view/delete-game) renders at the foot in its `inline` size with the label "Borrar".
