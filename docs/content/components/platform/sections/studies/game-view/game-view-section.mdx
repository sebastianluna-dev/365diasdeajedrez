## Purpose

Where a game is read **and** annotated, in the same place. There is no separate editing screen: whoever owns the game plays on the board to add moves and uses the list's right click to comment, annotate, promote or delete them, and all of it saves by itself.

The PGN lives here because two things write it: the [`GameViewer`](/components/chess/game-viewer/game-viewer) (moves, arrows, structure) and the [`GameTools`](/components/platform/sections/studies/game-view/game-tools) panel under the board (comment, NAGs, review). If each kept its own copy, commenting a move would not show in the list until reload.

| `errorCode` | `string`   | no       | What bounced back from an action, translated by `STUDY_ERROR_MESSAGES`: the game's (`gameInClasses`) and the study's (`confirmStudyDelete`, `fen`, the common codes), whose forms live in the aside. |

## Behaviour

- **PGN and history in one reducer.** `pgnReducer` holds `{ pgn, past }`; an `edit` pushes the previous PGN (ignoring no-op edits, which would spend an undo step that undoes nothing) and keeps the last 50; `undo` pops. Storing whole PGNs is a few kilobytes each and cannot drift, unlike a log of inverse operations. Ctrl+Z / ⌘Z undoes when `canEdit`, except while typing in a field, where the field's own undo rules.
- **Controlled path.** `currentPath` goes back and forth with the viewer so the evaluation chart can move the board.
- **Tools tab and focus.** `toolsTab` starts at "comment" for editors and "share" otherwise; the viewer's `onRequestEdit` switches the tab and bumps `focusRequest`, a counter rather than a boolean so two requests on the same tab are distinguishable.
- **Autosave.** With `canEdit`, 1.2 s after the last change the latest PGN goes to `autosaveGamePgn(studyId, gameId, pgn)`; a change during the wait restarts the timer. `lastSaved` is what the server confirmed; "unsaved" is derived by comparison. The label shown in the tools bar prioritises error, then saving, then unsaved, then saved.
- **Leaving.** A `beforeunload` handler warns when `pgn !== lastSaved`.
- **Players.** The internal `Player` renders the strips: colour chip, federation code with its flag from `federationFlag` (nothing painted for unknown codes), title, name, Elo. Passed by colour because the viewer can flip.
- The viewer is mounted with `controls="panel"` (in studies the game is traversed from the list), `engine`, no header (the players are already in the strips and the aside; a header stole height from the moves).

## Usage

From `app/(platform)/estudios/[studyId]/partidas/[gameId]/page.tsx`:

```tsx
import { GameAside } from "@/components/platform/sections/studies/game-view/game-aside.comp";
import { GameViewSection } from "@/components/platform/sections/studies/game-view/game-view.section";

<div className="game-page__layout">
  <GameAside
    game={game}
    study={study}
    results={results}
    classGames={classGames}
    kinds={kinds}
    students={students}
    pageHref={pageHref}
  />
  <GameViewSection game={game} errorCode={error} />
</div>;
```

The page loads the game (its first await, the session border), the study on the page of games the current one falls on (`getStudyPageOfGame`, or `?pagina=`) and the catalogs, and hands them over: what each column shows is decided inside it.
