## Purpose

Where a game is read **and** annotated, in the same place. There is no separate editing screen: whoever owns the game plays on the board to add moves and uses the list's right click to comment, annotate, promote or delete them; all of that saves by itself.

The section only wires the two things the viewer cannot own: the PGN's history, because two things write the PGN (the viewer and the tools under the board) and a third reads it (the autosave), and the autosave itself, which is a server action. Everything else — the strips, the tools panel with its tab and focus, the path, the engine — is the viewer's, fed with data.

## Props

| Prop           | Type                      | Required | Meaning                                                                                                                                                                                                                                           |
| -------------- | ------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `game`         | `GameView`                | yes      | The game with `pgn`, `canEdit`, players (name, Elo, title, country), record fields and `studyId`.                                                                                                                                                 |
| `asReader`     | `boolean`                 | no       | The owner asked to see the game as a reader (`?vista=lector` on the page): nothing is edited or saved, and the game's analysis mode applies.                                                                                                      |
| `errorCode`    | `string`                  | no       | What bounced back from an action, translated by `STUDY_ERROR_MESSAGES`: the game's (`gameInClasses`) and the study's (`confirmStudyDelete`, `fen`, the common codes), whose forms live in the aside.                                              |
| `importReport` | `PgnImportReport \| null` | no       | The result of the PGN import that has just happened (`?importadas=`, read by the page with `readImportReport`). The notice goes above the board, like an error: «Se importaron N partidas.», or how many of how many and why the rest stayed out. |

## Behaviour

- **`usePgnHistory(game.pgn, { undo: game.canEdit })`** gives the PGN the viewer renders, `applyPgn` for whatever the viewer or the tools write, and the ⌘Z / Ctrl+Z undo (off for a game one cannot edit).
- **`useGameAutosave({ studyId, gameId, pgn, enabled: game.canEdit })`** saves 1.2 s after the last change and gives `saveLabel`, which goes to the viewer's `tools` so the panel says "sin guardar", "guardando…", "guardado" or "no se pudo guardar".
- The viewer is mounted with `controls="panel"` (in studies the game is traversed from the list), `engine`, no header (the players are already in the strips and the aside; a header stole height from the moves), `players` as data (name, Elo, title, federation per colour) and `tools={{ saveLabel }}`.
- **The game's settings** reach the viewer as data: `orientation` from `game.orientationCode`, `pinnedComment`, and `hideNextMoves` when its analysis mode is `CONCEAL`. A mode is the reader's — the viewer ignores it while editing —, so the game's owner gets a line over the board that says which mode readers will see, with «Ver como lector», a link to the same page with `?vista=lector`; there the section mounts the viewer as a reader's (`canEdit` off: no undo, no autosave, no editing) and the line offers «Volver a editar».
- **The move it was left on** (2026-10-07). `useRememberedMove` drives the viewer (`path`, `onPathChange`) and keeps the move in this browser's `localStorage`, one key per game (`365:estudios:partida:<gameId>:jugada`), written on every move — at once, with nothing to send when the page closes —; opening the game again starts on that move. The server renders the start, which is all it can know; the browser's first render reads the stored move through `useSyncExternalStore`, so the board, drawn in the browser only, opens on it. A move the PGN no longer has is resolved by the viewer to its closest ancestor; what the viewer reports back that is the move it was given is an echo and is not written; blocked or cleared storage leaves the game at the start. Which **game** a study opens on is the server's ([`RememberOpenedGame`](/components/platform/sections/studies/game-view/remember-opened-game)); which **move**, this device's. The teacher's view of a student's game keeps its move too, in the teacher's browser.

## Markup & styling

Block `.game-view` (24 lines): the board column (`min-width: 0`), the margin under the notice and the owner's line about the readers' mode (`.game-view__mode`, `.game-view__mode-link`). The grid that puts it beside the study and the game's record is the layout's, `.game-page__layout` in `game-page.css`; the strips are [`PlayerStrip`](/components/chess/game-viewer/player-strip)'s.

**Other selectors it styles:** `.platform-notice` (margin inside the column).

No media queries of its own.

## Usage

From `app/(platform)/estudios/[studyId]/partidas/[gameId]/page.tsx`:

```tsx
import { GameRecord } from "@/components/platform/sections/studies/game-view/game-record.comp";
import { GameViewSection } from "@/components/platform/sections/studies/game-view/game-view.section";

<>
  <GameViewSection
    game={game}
    asReader={vista === "lector"}
    errorCode={error}
    importReport={readImportReport(importadas)}
  />
  <GameRecord game={game} results={results} />
</>;
```

The frame around the two — `.game-page__layout` and the study's column — is the layout's, `app/(platform)/estudios/[studyId]/partidas/layout.tsx`.
