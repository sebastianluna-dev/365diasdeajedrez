## Purpose

Where a game is read **and** annotated, in the same place. There is no separate editing screen: whoever owns the game plays on the board to add moves and uses the list's right click to comment, annotate, promote or delete them; all of that saves by itself.

The section only wires the two things the viewer cannot own: the PGN's history, because two things write the PGN (the viewer and the tools under the board) and a third reads it (the autosave), and the autosave itself, which is a server action. Everything else — the strips, the tools panel with its tab and focus, the path, the engine — is the viewer's, fed with data.

## Props

| Prop        | Type       | Required | Meaning                                                                                                                                                                                              |
| ----------- | ---------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `game`      | `GameView` | yes      | The game with `pgn`, `canEdit`, players (name, Elo, title, country), record fields and `studyId`.                                                                                                    |
| `errorCode` | `string`   | no       | What bounced back from an action, translated by `STUDY_ERROR_MESSAGES`: the game's (`gameInClasses`) and the study's (`confirmStudyDelete`, `fen`, the common codes), whose forms live in the aside. |

## Behaviour

- **`usePgnHistory(game.pgn, { undo: game.canEdit })`** gives the PGN the viewer renders, `applyPgn` for whatever the viewer or the tools write, and the ⌘Z / Ctrl+Z undo (off for a game one cannot edit).
- **`useGameAutosave({ studyId, gameId, pgn, enabled: game.canEdit })`** saves 1.2 s after the last change and gives `saveLabel`, which goes to the viewer's `tools` so the panel says "sin guardar", "guardando…", "guardado" or "no se pudo guardar".
- The viewer is mounted with `controls="panel"` (in studies the game is traversed from the list), `engine`, no header (the players are already in the strips and the aside; a header stole height from the moves), `players` as data (name, Elo, title, federation per colour) and `tools={{ saveLabel }}`.

## Markup & styling

Block `.game-view` (11 lines): the board column (`min-width: 0`) and the margin under the notice. The two-column grid beside the aside is the page's, `.game-page__layout` in `game-page.css`; the strips are [`PlayerStrip`](/components/chess/game-viewer/player-strip)'s.

**Other selectors it styles:** `.platform-notice` (margin inside the column).

No media queries of its own.

## Usage

From `app/(platform)/estudios/[studyId]/partidas/[gameId]/page.tsx`:

```tsx
import { GameAside } from "@/components/platform/sections/studies/game-view/game-aside.comp";
import { GameViewSection } from "@/components/platform/sections/studies/game-view/game-view.section";

<div className="game-page__layout">
  <GameAside
    game={game}
    study={study}
    results={results}
    classGames={classGames}
    kinds={kinds}
    students={students}
    pageHref={pageHref}
  />
  <GameViewSection game={game} errorCode={error} />
</div>;
```
