## Purpose

The one card of the study's column that is about the **current game**. It was the second card of `GameAside` until 2026-10-05, when the study's part of that column moved to the layout so as to hold still from game to game ([`StudyAside`](/components/platform/sections/studies/game-view/study-aside)); what depends on the game stayed with the page, and this is it.

**What it carries, and in what order** (2026-10-05, chosen by the owner among twelve options, «Pastillas»). The card had the event, the place and a two-by-two grid of labelled cells — Fecha, Ronda, ECO, Resultado. Now:

- the **event** is its title;
- under it, **one line**: «Ronda 1 · 3 de junio, 2026 · Oaxtepec», whichever of the three the game has;
- then **pills**, an icon and a short fact each: the opening's ECO code and the number of moves.

The **result is gone** from the card: the list of games and the players' strips already say it, and here it was the third time. The round left its cell — a «1» alone in a quarter of the card — and joined the line about the tournament. The number of moves is new. The text is a step under what it was, level with the rest of the page: the label, the line and the pills in `xs`, the event in `md`, under the study's name in `lg`.

Not here yet, though the options showed them: the **opening's name** beside its code (it needs a table of names by ECO, which does not exist), the **time control** and **how the game ended** (they are headers of the PGN that nothing stores as columns).

## Props

| Prop      | Type                | Required | Meaning                                                                                    |
| --------- | ------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `game`    | `GameView`          | yes      | The current game.                                                                          |
| `results` | `StudyKindOption[]` | yes      | The results catalog, for the edit dialog. Empty when the game is not the viewer's to edit. |

## Behaviour

- **Only what the game has is drawn.** A fact that is missing takes no place — no cell with a dash, as the grid had —, so the card is as tall as its game is documented: from a label and one pill for a game just started to the full card. A game with nothing at all says «Esta partida aún no tiene datos.».
- **The line** is `contextOf`: «Ronda N», the date as `playedAtLabel` writes it and the site, joined with « · ».
- **The moves** are `game.moveCount`: moves of the main line as a player counts them (White's and Black's are one), which the mapper takes from the position index (`_count.positions`, one row per ply and the starting position) without reading the PGN. «1 jugada», «43 jugadas»; nothing for a game with no move.
- **Each pill's icon is its label for the eye**; the opening's also carries «Apertura, código ECO:» for a screen reader (`.game-record__sr`), since «D94» alone says nothing read out.
- With `game.canEdit`, [`EditGame`](/components/platform/shared/edit-game) sits at the end of the head with its pencil trigger (`trigger="icon"`) and `values={game}` whole (`GameView` already contains every field of `GameFieldValues`; listing them one by one is how the title and the federation got lost once).
- **No foot** (2026-10-05). The card ended with where the game came from («Importada de PGN»…) and, for its owner, «Eliminar»; the owner took both out. A game is deleted from its settings, behind the gear of its row in the list ([`GameSettings`](/components/platform/shared/game-settings)), which since then asks for what `DeleteGame` — the dialog that button opened, removed with it — asked of a game some class shows. The game's origin is still in `GameView.sourceLabel`, which the teacher's view of a student's game shows.
- **`GameRecordSkeleton`**, exported beside it, is the card blank (`.game-record_state_loading`, 170px tall, `aria-hidden`): what the game's `loading.tsx` puts in the record's place while the next game of the study arrives, next to [`GameSkeleton`](/components/platform/sections/studies/game-view/game-skeleton).

## Markup & styling

Block `.game-record` (97 lines), a `<section>`: white on the page's grey over a light shadow, with no outline, like every box of the game view. A column: the head (the label and the pencil), the event, the line, the pills, which wrap.

**Elements:** `.game-record__head`, `.game-record__label`, `.game-record__event`, `.game-record__context`, `.game-record__facts`, `.game-record__fact`, `.game-record__fact-icon`, `.game-record__sr`

**Modifiers and states:** `.game-record_state_loading`

**Other selectors it styles:** `.edit-game` in the head (negative margins, so the 28px pencil neither makes the head taller nor sits inside the card's text edge).

**Tokens:** `--platform-surface`, `--platform-surface-neutral` (the pills), `--platform-text-muted` (their icons), `--platform-text-subtle`

No media queries of its own: where it goes — under the study on a wide window, beside it on a tablet, under it on a phone — is the page's (`.game-page__layout` in `game-page.css`, see [`StudyAside`](/components/platform/sections/studies/game-view/study-aside)).

## Usage

From `app/(platform)/estudios/[studyId]/partidas/[gameId]/page.tsx`:

```tsx
import { GameRecord } from "@/components/platform/sections/studies/game-view/game-record.comp";

<>
  <GameViewSection
    game={game}
    asReader={vista === "lector"}
    errorCode={error}
    importReport={readImportReport(importadas)}
  />
  <GameRecord game={game} results={results} />
</>;
```

The page asks for the results only when `game.canEdit`.
