```ts
  initialPgn: string,
  options: { undo: boolean },

```

## Behaviour

- `pgnReducer` holds `{ pgn, past }`: an `edit` pushes the previous PGN and keeps the last `HISTORY_LIMIT` (50); `undo` pops, and with nothing to pop returns the same state. Storing whole PGNs — a game is a few kilobytes — is infinitely simpler than a log of inverse operations and cannot drift out of sync.
- An `edit` with the same PGN is ignored: it would spend an undo step that undoes nothing, and the first Ctrl+Z would seem not to work.
- With `undo` on, ⌘Z (Ctrl+Z) undoes the last change, except while typing in a textarea, an input or a contentEditable, where the field's own undo rules.
