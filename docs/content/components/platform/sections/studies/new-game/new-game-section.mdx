## Purpose

Creating a game on a page of its own: the full data set through [`GameFields`](/components/platform/sections/studies/game-fields), plus a PGN box (a single game; its headers fill whatever was left blank) and a FEN box for games that start from a diagram. Everything is optional: submitting the empty form creates a blank game and opens the board, the short path to start analysing without a PGN or knowing who played.

This is a second door to the same action as the "Crear vacía" tab of [`NewGame`](/components/platform/sections/studies/study-detail/new-game); nothing links to it from the interface today (`IMPROVEMENTS.md` #29).

## Props

| Prop        | Type                | Required | Meaning                                                                            |
| ----------- | ------------------- | -------- | ---------------------------------------------------------------------------------- |
| `study`     | `StudyDetail`       | yes      | For the breadcrumb, the cancel link and the next chapter number in the title hint. |
| `results`   | `StudyKindOption[]` | yes      | The results catalog.                                                               |
| `errorCode` | `string`            | no       | `?error=`; `fen` is the only code with a message here.                             |

## Behaviour

`<form action={createStudyGame.bind(null, study.id)}>` with two cards: the data and the starting point. The PGN textarea is capped at `PGN_MAX_LENGTH`. The action creates the game and redirects to its view; an invalid FEN bounces back to this page with `?error=fen`.
