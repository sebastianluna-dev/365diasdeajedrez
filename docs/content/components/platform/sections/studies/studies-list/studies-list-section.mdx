## Purpose

The whole of «Mis estudios», moved to the new design system on 2026-10-23 («M4» of the owner's canvas, `MaterialM4Estudios`). The page bleeds onto the canvas (`platform-page_width_full` + `platform-page_frame_bleed`) and this section draws the workspace:

- **The side column** (`.platform-workspace__side`): «Nuevo estudio» as Material's extended FAB ([`NewStudy`](/components/platform/sections/studies/studies-list/new-study): a button, since it opens a popup, and not the side nav's own action, which is a link), and under it a [`PlatformSideNav`](/components/platform/shared/platform-side-nav) with two groups: **«Tipos»** — «Todos», «Mis partidas», «Estudios», «Torneos», «Colecciones» when they own one, «Recibidos» when they received something —, each with its count, and **«Ordenar»** — «Recientes», «Nombre», «Más partidas» —, as a choice of one with a radio's ring.
- **The panel** (`.platform-workspace__panel`): the notice of what `createStudy` bounced back with, and the library, [`StudiesBrowser`](/components/platform/sections/studies/studies-list/studies-browser).

## Props

| Prop           | Type                | Required | Meaning                                                                         |
| -------------- | ------------------- | -------- | ------------------------------------------------------------------------------- |
| `studies`      | `StudySummary[]`    | yes      | `getUserStudies()`, read by the page in parallel with `getStudyKinds()`.        |
| `kinds`        | `StudyKindOption[]` | yes      | `getStudyKinds()`: the kinds the viewer can create, for «Nuevo estudio».        |
| `view`         | `StudyView`         | yes      | The kinds on screen, from `?tipo=` (`studyViewOf`): `undefined` is «Todos».     |
| `sort`         | `StudySort`         | yes      | The order, from `?orden=` (`studySortOf`): `undefined` is «Recientes».          |
| `query`        | `string`            | no       | `?q=`, a search sent from a study's bar, which the library opens with.          |
| `errorMessage` | `string`            | no       | What `createStudy` bounced back with, already in words (`studentErrorMessage`). |

## Behaviour

- **A view is an address.** The links of the side column carry `?tipo=` and `?orden=`, each keeping the other (`studiesHref`), so a view can be shared and the back button undoes it, as on «Cursos». The page reads them and this section filters and orders on the server (`studiesOfView`); the lit link is the one whose values match. A value the page does not know is «Todos» or «Recientes». Until 2026-10-23 they were tabs and a select inside the library, held in the browser's state.
- **The counts** are the library's, whatever is searched: «Todos» every study, a kind the viewer's own of that kind, «Recibidos» what is not theirs. «Mis partidas», «Estudios» and «Torneos» are always listed (every student has a place for them); «Colecciones» and «Recibidos» only when there is one.
- **«Recientes»** orders by `recentAt` (when the viewer last opened a game of the study, `StudyVisit.openedAt`, or its creation), «Nombre» by Spanish collation without case, «Más partidas» by size.
- **«Sigue donde ibas»** is given only on «Todos»: the study whose game was opened last, while that game is there (`resumeStudyOf`).
- **The split is by ownership**, not by kind (`isOwnStudy`, `permissions.canEditGames`): what the student can edit goes to `own`; what reaches them ready-made and read-only (a teacher's collections, the games of their classes) goes to `received`. The collections of the courses they started are not in the list since 2026-10-02 (`getUserStudies` reads `getListedDatabasesWhere`).

## Usage

From `app/(platform)/estudios/page.tsx`:

```tsx
import { StudiesListSection } from "@/components/platform/sections/studies/studies-list/studies-list.section";

<div className="platform-page platform-page_width_full platform-page_frame_bleed">
  <StudiesListSection
    studies={studies}
    kinds={kinds}
    view={studyViewOf(tipo)}
    sort={studySortOf(orden)}
    query={q}
    errorMessage={studentErrorMessage(error) ?? undefined}
  />
</div>;
```
