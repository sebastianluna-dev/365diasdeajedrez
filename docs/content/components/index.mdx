# Components: map & rules

`components/` mirrors the products in `app/`, and this section mirrors `components/`: **one page per file**, at the same path (`components/site/sections/home/hero/hero.section.tsx` → `/components/site/sections/home/hero/hero-section`). Each page says what the file is for, whether it runs on the server or the client, what it receives, who renders it, how it behaves, what it paints and how it is mounted in real code.

```text
components/
  chess/                the chess domain, shared by the public site and the platform (React side of lib/chess)
  icons/                one SVG icon component per file, used by every product
  site/                 = app/(frontend)
    sections/           shell/ home/ nosotros/ blog/ chess-clock/
    shared/             logo, google-analytics, meta-pixel
  platform/             = app/(platform)
    sections/           shell/ dashboard/ courses/ studies/ classes/ explorer/ trainer/ teacher/ staff/
    shared/             form-field, platform-table, platform-notice, empty-state, board-loading, local-datetime…
  auth/                 = app/(auth)
    sections/           login/
```

| Page                             | Covers                                                                                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Public site](/components/site)  | `site/shared` and every section of the home page, the about page, the blog and the chess clock: one page per file.                                                                       |
| [Platform](/components/platform) | `platform/shared` and every section of the student, teacher and staff screens: one page per file.                                                                                        |
| [Auth](/components/auth)         | `auth/sections/login`: one page per file.                                                                                                                                                |
| [Chess](/components/chess)       | `chess/`: one page per file for the board, the viewer and its parts, the analysis board, the diagram. The narrative of how they fit together is in [Board & game viewer](/chess/viewer). |

## Rules

- **One product per folder.** A component belongs to `site/`, `platform/` or `auth/`, or to the `chess/` domain. There is no `common/` folder: if two products need the same piece and it is not chess, that is a design smell to look at, not a folder to create.
- **`sections/` vs `shared/`.** Inside a product, `sections/<area>/<section>/` holds a page section (`*.section.tsx`) together with the `*.comp.tsx` pieces only that section uses. `shared/` holds pieces reused by several sections of the same product. A piece used by exactly one section stays next to it.
- **Server by default.** `"use client"` goes on the leaf that owns state or touches a browser API, never on a section that could stay on the server. The reference pages mark every client component.
- **One stylesheet per component**, same base name, imported by that component, with every rule nested under its BEM block (see [Styling](/ui/styling)). Entries say whether a component has one.
- **Sections read, pieces render.** A section may call a service or receive props from its page; a `.comp.tsx` receives props only. Writes go through server actions bound in the section.
- **Naming.** kebab-case files with the `.section.tsx`, `.comp.tsx`, `.hook.ts` suffixes; PascalCase exports; no barrels; imports through `@/components/...`.

## How a page is laid out

Every component page follows the same template, so the same fact is always in the same place:

| Markup & styling                     | The block, its elements, modifiers and states, the tokens and breakpoints it uses, and any other class it renders. The block's line count, «(N lines)», is the stylesheet's own: `components/docs-line-counts.test.ts` fails when they differ.                                    |
| Usage                                | A snippet copied from a real importer.                                                                                                                                                                                                                                            |

A component with a Storybook story adds a **Story** row after **Stylesheet**, with the story file and its title; how to write one is in [Storybook](/ui/storybook). Every piece of `components/platform/shared/` has one (`ImageUpload` aside, until its server action can be mocked), and `components/stories.test.ts` checks this row on every page whose component has a story.

The pages are written from the code and kept in the same commit as any change to a component: rename a prop, update the row; add a file, add its page; delete a file, delete its page. `_meta.ts` files give the sidebar its titles (the main export) and its order (section first, then its pieces).

## Icons — `components/icons/`

Two hundred and thirty-four SVG components, one per file: 231 icons of **Font Awesome Pro 7.3.1**, each in three styles, plus `LogoMarkIcon` and `LogoWordmarkIcon` (the brand's) and `WhatsappIcon` (WhatsApp's logo). Each is an inline `<svg>` with `viewBox`, `fill="currentColor"` and `aria-hidden="true"`; colour and size come from the caller's CSS, and an icon that stands alone needs its text in the button's `aria-label`. `LogoWordmarkIcon` paints nothing by itself (`fill="none"`): its caller colours its three groups through `accentClassName`, `wordClassName` and `marksClassName`, and it also exports `LOGO_LABEL`, the accessible name of the link that wraps it.

### Names and the `variant` prop

- **Named as Font Awesome names it.** The icon `chess-knight` is `ChessKnightIcon`, in `chess-knight-icon.comp.tsx`; to find an icon, search fontawesome.com and write its name. The names say what is drawn, not what it is for: the move viewer's "back" is `ChevronLeftIcon`, settings are `SlidersIcon` (three sliders: a cog at 19 px turns to mush), `GearIcon` is the cog. The old names (`ArrowLeftIcon` for the chevron, `CloseIcon`, `MenuIcon`, `FlameIcon`…) were changed on 2026-10-03.
- **`variant`: the Font Awesome style, by its Font Awesome name.** Every Font Awesome icon takes `IconProps` from `icon-variant.const.ts`: `className` and `variant`, which is `"duotone-light"` (the default), `"duotone-solid"` or `"classic-solid"` (`ICON_VARIANTS`); all three drawings are pasted in the icon's file. A caller that draws a filled shape asks for Duotone Solid: `PlayIcon`, `PauseIcon`, `ForwardStepIcon`, `BackwardStepIcon`, `CaretRightIcon`, `HeartIcon`, `FireIcon`, `GripDotsVerticalIcon` and `EllipsisIcon` are drawn Solid where they are used, and so is `CircleCheckIcon` as the mark of what is done (a finished chapter, a learned lesson), next to its Light self in a plan card's list. `FireIcon` takes one more class, `coreClassName`, for the Duotone front layer its caller paints (the inner flame in Duotone Solid; Classic Solid is one shape and has none). Classic Solid, one shape and no second tone, is there for what has to read as a plain silhouette; nothing in the app asks for it yet.
- **Two layers.** A Duotone icon is two `<path>`s: the one at the back carries `opacity=".4"`, the one in front is drawn whole. A Duotone drawing that is only a back layer (Duotone Solid's `play`, `pause`, `caret-right`, `heart`, `circle`…) is drawn at full strength, since at 40 % it reads as switched off; `FireIcon`'s back layer, the fire, is also at full strength.
- **The margin is in the `viewBox`.** Font Awesome draws to the edge of its em box; the hand-drawn icons the set replaced had a margin inside their 24 px grid. So that no caller's stylesheet had to change, an icon is `24 × 24` (or the size its old one had) and its `viewBox` is a square 1/0.75 the height of the em box (`512 / 0.75 ≈ 682.67`), centred on it: the glyph fills 75 % of the box. The icons that already used a Font Awesome em box (`CaretRightIcon`, `CircleCheckIcon`, `GripDotsVerticalIcon`, `HeartIcon`, `PlusIcon`) keep it; `EllipsisIcon` is cut close around its dots for its 16×4 box; `FireIcon` keeps the room above its em box, where the fire peeks out.

### The library

The 38 icons the app draws are in the table below; the other 193 are there so that a new screen picks its icon from the set instead of drawing one: the chess pieces (`ChessKnightIcon`, `ChessKingPieceIcon`…, `ChessBoardIcon`, `ChessClockIcon`), learning (`GraduationCapIcon`, `BookOpenIcon`, `PuzzlePieceIcon`, `TrophyIcon`, `MedalIcon`, `LightbulbIcon`, `StopwatchIcon`…), arrows and chevrons in every direction, the usual actions (`PenToSquareIcon`, `CopyIcon`, `DownloadIcon`, `ShareNodesIcon`, `FilterIcon`, `EyeIcon`, `LockIcon`, `BellIcon`…), states (`CircleExclamationIcon`, `TriangleExclamationIcon`, `CircleQuestionIcon`, `SpinnerIcon`…) and the media controls. Being unused costs nothing: each file is its own module, and a page only ships the icons it imports.

### Where the drawings come from

The set was chosen on 2026-10-03 over Material Symbols and the other Font Awesome styles, after comparing them against the old hand-drawn icons. Each icon is pasted into its component from its SVGs, never loaded at run time: no Kit script (it would need the CSP opened to Font Awesome's hosts, swaps the icons in the browser and counts pageviews against the plan) and no `@fortawesome` package (it needs a token in CI and Vercel). Each component ends its doc comment with Font Awesome's attribution and "Commercial License". The Pro licence lets the icons be embedded in the site but not published as files anyone can copy, so **the repository must stay private** while they are in it.

To add an icon: take its three SVGs from fontawesome.com (signed in with the subscription), Duotone Light, Duotone Solid and Classic Solid, and write `<name>-icon.comp.tsx` like its neighbours: `IconProps`, the three drawings behind `variant`, the back paths with `opacity=".4"`, the 75 % `viewBox`, the attribution. Then add it to the gallery story.

The Storybook page `icons/Gallery` (`components/icons/gallery.stories.tsx`) draws them, each with its export under it: `AtAppSize`, the icons the app draws, at the size and in the weight their main caller asks for; `LargeInAccent`, the whole library in a 48px box in the accent, in its three styles. The wordmark is drawn there by its real caller, the site's `Logo`.
