## Purpose

The `/blog` page. It used to be a Client Component that received every article, body included, and filtered in `useState`, so nothing beyond the first page had an address of its own. Now the page parses `searchParams` into an `ArticleListingQuery`, this section calls `selectArticles` to filter and paginate, and `listingHref` builds every link, so a category or a page can be shared, indexed and reached with the back button.

## Props

| Prop | Type | Required | Meaning |
| --- | --- | --- | --- |
| `articles` | `ArticleSummary[]` | yes | Every summary; filtering happens here. |
| `query` | `ArticleListingQuery` | yes | `category` and `page`, already validated by `parseListingQuery` in the page. |

## Behaviour

- `selectArticles(articles, query)` returns `categories`, `category`, `items`, `page`, `totalPages`, `totalItems`.
- The filter's `hrefFor` resets to page 1; the pagination's keeps the category.
- Each card receives `--blog-card-index` as an inline custom property so the CSS can stagger its entrance.

## Usage

From `app/(frontend)/blog/page.tsx`:

```tsx
import { BlogArticles } from "@/components/site/sections/blog/blog-articles/blog-articles.section";

<Header theme="light" />
<main id="contenido">
  <BlogArticles articles={articles} query={query} />
</main>
<Footer accent="red" />
```
