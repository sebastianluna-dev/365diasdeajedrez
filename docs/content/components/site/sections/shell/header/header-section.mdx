## Purpose

The navigation bar every public page opens with. Its items come from the CMS so editors can add or reorder links; its main button does not. That button is the entrance to the platform, so its text ("Iniciar sesión") and its target (`LOGIN_PATH`) are fixed in code: an editable label could end up promising something different from what the link does. The `ctaLabel` field of the `home-header` Global still exists and `services/home` still maps it, but nobody reads it any more.

## Props

| Prop    | Type                | Required     | Meaning                                                                              |
| ------- | ------------------- | ------------ | ------------------------------------------------------------------------------------ |
| `theme` | `"dark" \| "light"` | no, `"dark"` | `"light"` is the blog's variant: red-accent logo and `.site-header-nav_theme_light`. |

## Behaviour

- Awaits `getHeaderData()` and maps `navItems`: a `link` item becomes a `next/link`, a `dropdown` item becomes a [`HeaderDropdown`](/components/site/sections/shell/header/header-dropdown).
- Renders the desktop login button and hands the same label and href to [`HeaderMobileMenu`](/components/site/sections/shell/header/header-mobile-menu), so both menus agree without the CMS.
- `.site-header-nav__spacer` reserves the bar's height so the fixed bar does not overlap the first section.

## Markup & styling

Block `.site-header-nav` (324 lines, shared by the three header files).

**Elements:** `.site-header-nav__inner`, `.site-header-nav__spacer`, `.site-header__links`, `.site-header__button`, `.site-header__toggle`, `.site-header__dropdown`, `.site-header__dropdown-trigger`, `.site-header__dropdown-menu`, `.site-header-mobile__links`, `.site-header-mobile__button`

**Modifiers:** `.site-header-nav_theme_light`, `.site-header__dropdown_open`, `.site-header-mobile_open`

**Tokens:** `--color-primary`, `--color-accent-red`, `--color-dark`, `--foreground`

**Breakpoints:** `(max-width: 1023px)` hides the desktop links and button and shows the toggle.

The toggle is `position: fixed`, so it cannot be centred by the layout: its `top` is `calc(25px + (var(--site-logo-height) - 40px) / 2)` — the bar's top padding on mobile plus the difference between the wordmark and the 40 px button — and the mobile menu opens 16 px under it, from the same expression. Both follow the logo's height on their own; the number to revisit is the 25 px, if the bar's padding changes. The height the whole header occupies is published as `--site-header-height` for the home hero to read (see [Styling › Tokens](/ui/styling#tokens)).
