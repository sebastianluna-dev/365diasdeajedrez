# Routes & URLs

URLs are Spanish because the product is. The single source of truth for private-area hrefs is `lib/platform-routes.ts` (`platformRoutes`, `teacherRoutes`, `staffRoutes`, `homeRouteFor(roles)`); components never build them from strings.

## Public site — `app/(frontend)`

| URL                                               | Rendering                   | Notes                                                                                                                                              |
| ------------------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                               | Static, `revalidate = 3600` | Composed from Payload Globals; regenerated by the Globals' `afterChange` hooks. Visitors with a session cookie are sent to `/entrar` by the proxy. |
| `/blog`, `/blog?categoria=…&pagina=…`             | Dynamic (search params)     | Listing of published article summaries, 9 per page, category filter in the URL.                                                                    |
| `/blog/[slug]`                                    | Dynamic                     | Article with Lexical content and chess blocks; canonical + Open Graph `article`.                                                                   |
| `/nosotros`                                       | Static                      | About page.                                                                                                                                        |
| `/mentor/[slug]`                                  | Dynamic                     | Mentor profile from the `home-mentors` Global, with a lazy board.                                                                                  |
| `/reloj-de-ajedrez`                               | Static                      | Chess clock (client component), one instance chosen by viewport.                                                                                   |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image` | Generated                   | `app/sitemap.ts`, `app/robots.ts`, `app/(frontend)/opengraph-image.tsx`.                                                                           |

## CMS — `app/(payload)`

| URL      | Notes                                                                                                                                    |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/admin` | Payload admin UI (its own login, its own users).                                                                                         |
| `/api/*` | Payload REST API. GraphQL is **disabled** (`graphQL: { disable: true }`); the site reads Payload through the local API, never over HTTP. |

## Access — `app/(auth)`

| URL                      | Notes                                                                                                                                                                      |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/iniciar-sesion?next=…` | Login page. A plain server action, so it works without JavaScript. `next` must be an internal path (`safeReturnTo`).                                                       |
| `/entrar`                | Route handler. Reads the real session and redirects to `homeRouteFor(roles)`; if the cookie is stale it deletes it and returns to `/`. `Cache-Control: private, no-store`. |

## Identifiers in URLs

| Entity                    | Id                                                                                                                                                 | Why                                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Course, lesson            | 8 random digits, zero-padded (`/cursos/00020212`, `/cursos/00020212/1/02482009`), generated by `lib/numeric-id.ts` and used as the **primary key** | Readable, not enumerable, no second column to keep in sync.                                              |
| Chapter (student URL)     | Its `order` inside the course (`/cursos/00020212/1`)                                                                                               | It is the number the student sees; reordering reassigns URLs, as expected of an order number.            |
| Course (information page) | Its `slug` (`/cursos/mis-60-memorables-partidas`)                                                                                                  | The page that is shared and the staff links to: it says what the course is, to whoever has not added it. |
| Study, game               | `nanoid(8)` (`/estudios/aB3xK9pQ`)                                                                                                                 | Short enough for a URL, generated client-side by Prisma like `uuid()`.                                   |
| Everything else           | `uuid()`                                                                                                                                           | Staff URLs keep the internal ids; the two zones have different ids on purpose.                           |

**The lesson under its chapter.** The lesson is the one route that drags its course and its chapter along, and that is deliberate: `app/(platform)/cursos/[courseRef]/[chapterOrder]/(lesson)/layout.tsx` draws the column of lessons, and a layout is fetched once and is not rendered again while one moves inside it. Going from one lesson to the next therefore costs its PGN and nothing else — the column is not queried, not drawn and not scrolled back to the top. Two route groups keep them apart: `(chapter)/page.tsx` is the chapter's own screen, which does not get that layout, and `(lesson)/[lessonId]/` is the lesson. The segment is the lesson's **id**, not its order number: the id is what identifies it, what a teacher pastes into a class and what the old URLs carried. The page checks the course and the chapter of the URL against the lesson and sends a mismatch to its canonical address.

**One segment, two pages.** A dynamic segment cannot have two names, so `/cursos/[courseRef]` serves both the study view and the information page and tells them apart by the shape of the reference: eight digits is an id (`isCourseId`), anything else a slug. `resolveCourseReference` does it, and tries an id nobody has again as a slug. For that to be unambiguous the staff cannot save a slug that is id-shaped or `explorar` (`isReservedCourseSlug` in `services/courses/course-rules.ts`), which is a static folder next to the dynamic one. The study view and the chapters redirect to the information page when the student has not added the course.

## Protection

`constants/platform/auth.const.ts`:

```ts
export const PROTECTED_PATH_PREFIXES = [
  "/inicio",
  "/clases",
  "/estudios",
  "/cursos",
  "/ejercicios",
  // The lessons live under /cursos now; this one only redirects, and stays
  // protected so the redirect is not a way of learning that a lesson exists.
  "/lecciones",
  "/ajustes",
  "/entrenador",
  "/explorador",
  "/jugar",
  "/perfil",
  "/herramientas",
  "/profesor",
  "/administracion",
] as const;
```

- `proxy.ts` uses it for the optimistic redirect and repeats it **literally** in `config.matcher` (Next analyses the matcher at build time and discards computed values). The matcher also carries `/iniciar-sesion`, which is not protected but takes the platform's nonce policy ([Security headers](/operations/deployment#content-security-policy)). `proxy.test.ts` asserts the matcher equals the constant plus `/` and the login, and that the constant equals the folders of `app/(platform)`: a new folder left out of both fails it.
- `app/robots.ts` disallows the same prefixes plus `/iniciar-sesion`, `/entrar`, `/admin` and `/api`.
- The real check is always the DAL inside the page or action; the proxy cannot distinguish roles or expired sessions.

### Adding a platform route

1. Create the page under `app/(platform)/…`; its first `await` must be a service or `getCurrentUser()` (`requireTeacher()` / `requireStaff()` for the panels).
2. Add a builder to `lib/platform-routes.ts` and use it for every link.
3. If it is a new top-level prefix: add it to `PROTECTED_PATH_PREFIXES` **and** to the `matcher` in `proxy.ts`; run `npm test`.
4. Add it to the navigation in `constants/platform/nav-items.const.ts` only if it is a destination, not a step of another screen.
