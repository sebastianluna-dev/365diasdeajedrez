# Shared UI components

Everything reusable lives in three folders. Page-specific sections live under `components/sections/<area>/<section>/` and are not listed here.

| Folder | Content |
| --- | --- |
| `components/common/` | Primitives shared across the platform and the public site: tables, fields, notices, boards, navigation crumbs, uploads. |
| `components/ui/` | `SectionHeading`, the public site's eyebrow/title/description block. |
| `components/icons/` | One hand-written SVG icon component per file (`play-icon.comp.tsx` → `PlayIcon`). |
| `components/sections/common/` | Header, footer and site message of the public site. |

Everything is a **Server Component unless marked (client)**. The client ones are exactly those that own state or touch browser APIs; keep it that way when you add one.

## Platform primitives

### `PlatformTable`, `PlatformTableRow`, `PlatformTableCell` — `platform-table.comp.tsx`

A semantic `<table>` with one definition of the look for every list in the teacher and staff panels.

| Prop | Meaning |
| --- | --- |
| `columns` | `readonly (string \| { label, align?: "right" })[]`; rendered as `<th scope="col">`. |
| `children` | `PlatformTableRow` elements. When empty (after flattening arrays) the body shows `emptyLabel` in one full-width cell. |
| `emptyLabel` | Default "No hay nada que mostrar todavía." |
| `minWidth` | Minimum table width before the wrapper scrolls horizontally (default 640). |

`PlatformTableCell` takes `align="right"` and `strong` (the identifying column). There is no sorting or filtering state: filters travel in search params and the page filters on the server. `GameTable` in the study detail still draws its rows with `div`s; rebuilding it on this component is `todos.md` T13.

### `FormField`, `FormFieldset` — `form-field.comp.tsx`

Wraps a native control in a real `<label>` (never a placeholder acting as a label) and defines the input/select/textarea look for the whole authenticated area once. Props: `label`, `hint`, `error` (rendered with `role="alert"`), `children` (the control). `FormFieldset` does the same with `<fieldset>`/`<legend>` for groups of checkboxes or radios. No state: forms are `<form action={serverAction}>` and errors come back from the server.

### `PlatformNotice` — `platform-notice.comp.tsx`

The result of an action. Props: `message`, `variant` (`"error"` default, `"success"`, `"info"`). Rendered with `role="alert"`. Pages translate the `?error=<code>` search param with their message map and pass the text here.

### `EmptyState` — `empty-state.comp.tsx`

Dashed box with `title`, optional `description` and an optional link (`actionLabel` + `actionHref`). Use it instead of an empty table or a bare sentence.

### `ProgressIndicator` — `progress-indicator.comp.tsx`

`percent` (clamped to 0–100 and rounded), optional `detail`, `layout` `"inline"` (bar and label on one line) or `"stacked"` (percent and detail at the ends, bar below, as in the course card).

### `LoadingPanel`, `PlatformError`

`LoadingPanel({ label = "Cargando…" })` is what every `loading.tsx` under `app/(platform)` renders. `PlatformError` (client) receives `retry`, `message` and `digest` from `app/(platform)/error.tsx` and shows the digest so a user can quote it; the same digest appears in the server log line.

### `PriorityFilter` — `priority-filter.comp.tsx`

The "sólo lecciones imprescindibles" switch of a course: a `<form action>` with a bound server action (`setOnlyPriorityLessons`) and a button, no JavaScript. The next value travels as a bound argument rather than a checkbox because a checkbox cannot submit `false`. It is a per-course setting, so the same switch appears on the course and on the chapter page; `hiddenLessons` tells the user how many lessons the filter hides.

### `LocalDateTime` — `local-datetime.comp.tsx` (client)

Renders a UTC instant in the browser's time zone. Props: `iso`, `fallback` (the server-formatted text), `withTime`. It uses `useSyncExternalStore` with a server snapshot equal to `fallback`, so the HTML carries a correct date, there is no hydration mismatch, and the text is replaced by the local one once hydrated. Classes are stored in UTC and the server does not know the student's zone, which is why this exists.

### `CourseNavigation`, `StudiesNavigation`

Contextual breadcrumbs: Curso → Capítulo → Lección and Mis estudios → Estudio → Partida. Hrefs come from `lib/platform-routes.ts`; `current` marks which level is the page itself.

### `ActivityList` — `activity-list.comp.tsx`

The dashboard's recent activity: a `<ul>` of `ActivityItem` (`typeLabel`, `subjectName`, `topicLabel`, `dateLabel`) already labelled by the mapper.

### `ClassContentRenderer` — `class-content-renderer.comp.tsx`

Renders the ordered blocks of a class from the `ClassBlockView` discriminated union: `TEXT` as paragraphs (a line starting with `## ` becomes an `<h3>`), `VIDEO` and `FILE` as link cards, `GAME_REF` and `LESSON_REF` in the single `GameViewer` opened at `movePath` with a link to the full game or lesson, `POSITION_REF` in `StaticDiagram`. Used by the student's class page and the teacher's class detail.

### `ImageUpload` — `image-upload.comp.tsx` (client)

Drag-and-drop or pick an image, upload it straight from the browser to Cloudinary with a signature from `createUploadSignature()`, and leave the resulting URL in a hidden input (`name`, optionally `form`) that the surrounding server-action form saves like any other field. Props: `name`, `form`, `defaultValue`, `label`, `aspectRatio` (default `"21:9"`, applied as a Cloudinary crop through `withCoverCrop`), `hint`. The file is checked in the browser against `constants/platform/upload.const.ts` (jpg/png/webp/avif, 5 MB) for instant feedback, and Cloudinary enforces the same list because `allowed_formats` is part of the signature. The bytes never pass through the app's server, whose server actions have a 1 MB body limit.

### `LoginSubmit` — `sections/auth/login/login-submit.comp.tsx` (client)

The only client code on the login page: `useFormStatus()` disables the button and swaps the label to "Entrando…" while the plain server action runs. Without JavaScript the form still submits. `todos.md` T12 asks for a generic `SubmitButton` built from it and used by every write form.

## Icons

- `components/icons/<name>-icon.comp.tsx` exports `<Name>Icon({ className })`: an inline `<svg>` with `viewBox`, `fill="currentColor"` (or stroked) and `aria-hidden="true"`. Colour and size come from the parent's CSS.
- `lucide-react` is used only where it already was: the public header (chevrons, menu), the home teacher section and the mobile chess clock. Platform code uses the icons folder, not lucide, so the private bundle does not pull the library.
- An icon that conveys meaning on its own (no visible text next to it) needs the text in the button's `aria-label`, not in the SVG.

## Choosing and adding

| Need | Use |
| --- | --- |
| A list of records in a panel | `PlatformTable` (filters through search params). |
| A form control with a label | `FormField`; groups of checkboxes in `FormFieldset`. |
| Show the outcome of an action | `PlatformNotice` from the page's message map. |
| Nothing to show yet | `EmptyState` with a link to the action that creates the first item. |
| A date or time of a class | `LocalDateTime` with the server-formatted fallback. |
| A cover or photo | `ImageUpload` inside the form that will save the URL. |
| Anything with a board | see the [decision table](/chess/viewer#which-one-to-use) in the viewer page. |

When you add a shared component: kebab-case file with the `.comp.tsx` suffix, a named export, its own `.comp.css` nested under the block, `"use client"` only if it owns state, Spanish copy, and a row in this page.
