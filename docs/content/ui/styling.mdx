# Styling & design tokens

The project uses **plain CSS** only: no Tailwind (it was removed and its preflight replaced by a hand-written reset), no CSS Modules, no CSS-in-JS. There are about 180 stylesheets. Each one belongs to a single component or page and is imported there, except the two theme files described here.

## Two themes, two stylesheets

| File | Theme | Contains |
| --- | --- | --- |
| `app/(frontend)/globals.css` | **Dark** — the public site | The reset, the `--color-*` tokens, the board colours, base element styles (`html`, `body`, headings, links, forms), the global `:focus-visible` outline, the skip link, the hover transition rules and the `.section` / `.button` primitives. |
| `app/(platform)/platform.css` | **Light** — the authenticated area and the login page | The `--platform-*` tokens, `body.platform-theme` (which repaints the dark `body` from `globals.css`), a platform-coloured focus outline, and the `.platform-page` / `.platform-card` / `.platform-button` / `.platform-dialog` / `.platform-tag` primitives. |

Both files are global on purpose; every other stylesheet is scoped to its component.

### Which layout loads what

| Root layout | Stylesheets | `<body>` class | Font variables on `<html>` |
| --- | --- | --- | --- |
| `app/(frontend)/layout.tsx` | `globals.css` | none | `--font-gramatika`, `--font-suisse`, `--font-chessglyph` |
| `app/(auth)/layout.tsx` | `globals.css` + `platform.css` | `platform-theme` | the three above + `--font-sf-pro` |
| `app/(platform)/layout.tsx` | `globals.css` + `platform.css` | `platform-theme` | the three above + `--font-sf-pro` |
| `app/global-not-found.tsx` | `globals.css` | none | public fonts |
| `app/(payload)/layout.tsx` | Payload's own CSS + `custom.css` | Payload's | — |

`platform.css` always sits **on top of** `globals.css`: the reset, the element defaults and the transition rules come from the public sheet, and the platform sheet only swaps the palette and the font. That is why `body.platform-theme` exists: `globals.css` paints the body dark, and without that rule the scroll bounce on the platform would show black under the content.

## Tokens

Tokens are the only place a colour is chosen (plus `--site-header-height`, the one measurement that two stylesheets have to agree on). Component stylesheets use `var(--…)`; a bare hex value in a component is debt (the few that remain are listed in `todos.md` T14).

### Public site — `--color-*` (`globals.css`)

| Token | Value | Use |
| --- | --- | --- |
| `--background` / `--foreground` | `#16110d` / `#f2ede7` | Body background and text of the dark site. |
| `--color-dark` | `#16110d` | The brand dark; text on orange buttons. |
| `--color-primary` | `#ff9143` | Brand orange for fills (buttons, eyebrows, focus outline on dark). |
| `--color-primary-on-light` | `#f26c00` | Orange that stays legible as text on a light section. |
| `--color-primary-deep` | `#b8611f` | The button's hard shadow and the readable orange on light. Same value as `--platform-accent-ink`. |
| `--color-secondary` | `#f0c04b` | Yellow accent. |
| `--color-accent-red` / `--color-accent-red-on-dark` | `#a81e22` / `#f44046` | Red for light and dark backgrounds respectively. |
| `--color-muted-on-dark` / `--color-muted-on-light` | `#b4a99d` / `#5c5348` | Secondary text, one per background. |
| `--color-light-gray`, `--color-lighter-gray`, `--color-normal-gray` | `#e6e1dd`, `#eee9e5`, `#aca7a3` | Neutral surfaces and borders on light sections. |
| `--board-light` / `--board-dark` | `#eeeed2` / `#769656` | Board squares. Mirrored in `constants/chess-board-colors.const.ts` because the canvas export cannot read CSS; change both together. |
| `--site-header-height` | `100px`, `69px` under 1024 px | Vertical space the header occupies (the inner's top padding + the bar + the spacer). The only layout token: the home hero reads it to fill the first screen on mobile. Its value is composed by hand from `header.section.css`, so a change to the header's padding, the logo or the spacer has to be carried here. |

### Platform — `--platform-*` (`platform.css`)

The three brand colours keep their values and change roles: `#16110d` goes from background to text, and orange is reserved for **fills** (buttons, progress bars). As text on a light background that orange does not pass contrast, hence the separate ink token.

| Group | Tokens | Notes |
| --- | --- | --- |
| Surfaces | `--platform-bg` `#f6f4f1`, `--platform-surface` `#ffffff`, `--platform-surface-sunken` `#ede7de`, `--platform-surface-neutral` `#f2efea`, `--platform-surface-soft` `#fcfbf9` | Page, card, inset hollows (cover slot, empty cells), neutral chips, warm white for fields inside a white card. |
| Borders | `--platform-border` `#eae4dc`, `--platform-border-strong` `#e2dbd1` | Thin separates zones; strong outlines controls. |
| Text | `--platform-text` `#16110d`, `--platform-text-muted` `#6e655c`, `--platform-text-subtle` `#7a7168`, `--platform-text-faint` `#c3bbb1` | Body, secondary, small labels (subtle is 4.8:1 on white and may be used as text), and faint is **decoration only** (separator dots, row chevrons), never text. |
| Accent | `--platform-accent` `#ff9143`, `--platform-accent-hover` `#f07f2c`, `--platform-accent-ink` `#b8611f`, `--platform-accent-soft` `#fbeadb`, `--platform-accent-wash` `#fbf1e7` | Fill, fill on hover, orange as text/links/figures, tinted chip background, the faintest wash (active menu item). |
| Semantic | `--platform-success-{soft,ink,border}`, `--platform-danger` `#a81e22`, `--platform-danger-{soft,border}`, `--platform-warning-{soft,ink,border}` | Notices and tags. Each family has a background, an ink and a border of matching lightness. |
| Misc | `--platform-track` `#efeae3`, `--platform-shadow-card`, `--platform-shadow-bar`, `--platform-font` | Progress-bar track; on the light theme layers are separated by shadow, not by border; the single font stack (`var(--font-sf-pro)` with system fallbacks). |

`--transition-hover` is read by the global transition rule with a `150ms` default; a component may set it to change or remove the duration.

## Fonts

`next/font/local` loads woff2 subsets from `public/fonts/` and exposes them as CSS variables on `<html>`:

| Variable | Font | Where it is used |
| --- | --- | --- |
| `--font-gramatika` | Gramatika Bold | Public headings (`.section__title`, `.section-heading__title`). |
| `--font-suisse` | Suisse Intl 400/500/700 | Public body text (`body` in `globals.css`). |
| `--font-chessglyph` | ChessGlyph | Figurine notation. Not preloaded. |
| `--font-sf-pro` | SF Pro Display 400/500/700 | The whole platform, through `--platform-font`. Not preloaded. |

Platform stylesheets never name a font; they use `var(--platform-font)` or inherit it. See [Stockfish, pieces & sounds](/chess/engine-and-assets#fonts--publicfonts) for the subsetting commands and licences.

## BEM, nesting and scoping

The naming is Yandex-style BEM and the scoping is native CSS nesting. Both are mandatory for every component stylesheet.

- **Block** = the component's root class, in kebab-case: `.study-card`, `.platform-table`, `.game-viewer`.
- **Element** = `block__element`: `.study-card__title`. Elements are never nested in the name (`.study-card__head__title` is wrong; use `.study-card__head-title`).
- **Modifier** = `block_key_value` or `element_key_value`: `.platform-button_variant_secondary`, `.platform-table__cell_align_right`, `.progress-indicator_layout_stacked`. Boolean modifiers drop the value: `.site-header__dropdown_open`, `.logo__mark_hidden`.
- **One file per component**, named after it (`study-card.comp.css` next to `study-card.comp.tsx`) and imported from that component only.
- **Every rule nests under the root selector** with `&`, so nothing can leak out of the block. Media queries go inside the block too.
- **Desktop-first**: media queries use `max-width`. There is no fixed breakpoint scale; the ones used most are 1024/1023, 900 and 720 px, with 640/620 and 560 for the narrowest layouts. Pick the one where the layout actually breaks. Two files still use `min-width` (`section-heading.comp.css`, `resources.section.css`); inverting them is `todos.md` T17.

A complete example (`components/platform/shared/empty-state.comp.css`):

```css
.empty-state {
  border: 1px dashed var(--platform-border);
  border-radius: 10px;
  padding: 28px 24px;
  text-align: center;

  & .empty-state__title {
    margin: 0;
    font-size: 16.5px;
    font-weight: 600;
    color: var(--platform-text);
  }

  & .empty-state__description {
    margin: 6px 0 0;
    font-size: 15.5px;
    color: var(--platform-text-muted);
  }

  & .empty-state__action {
    display: inline-block;
    margin-top: 14px;
    font-size: 15.5px;
    font-weight: 600;
    color: var(--platform-accent-ink);
  }
}
```

Modifiers on the root use the compound form (`&.block_key_value`) so they still nest; a media query sits inside the element it changes (`components/chess/chess-board-lazy.comp.css`, abridged). Note the token fallbacks: this component also renders on the public site, where the `--platform-*` tokens do not exist.

```css
.chess-board-lazy {
  width: 100%;
  max-width: 800px;
  background: var(--platform-surface, #2b2723);

  & .chess-board-lazy__board {
    width: 58%;
    aspect-ratio: 1;

    @media (max-width: 720px) {
      width: 100%;
    }
  }

  & .chess-board-lazy__toolbar {
    height: 52px;
    border-top: 1px solid var(--platform-border, rgba(245, 240, 232, 0.07));
  }
}
```

```css
.section-heading {
  max-width: 48rem;

  &.section-heading_align_center {
    margin-left: auto;
    margin-right: auto;
    text-align: center;
  }
}
```

The React side mirrors this: modifiers are appended conditionally, and the class string is built in the component, never passed in from a parent (`className` props exist only on leaf primitives such as `EloTable` and the icons).

```tsx
<td className={`platform-table__cell${align === "right" ? " platform-table__cell_align_right" : ""}`}>
```

These are the only classes defined outside a component file, and they are meant to be used directly in JSX.

| `.button`, `.button_variant_primary`, `.button_variant_secondary`, `.button_size_hero` | `globals.css` | Public buttons. The primary one has the deep-orange hard shadow. |
| `.muted-text` | `globals.css` | Secondary text on light sections. |
| `.skip-link` | `globals.css` | Off-screen "Saltar al contenido" link, visible on focus; every layout renders it and every `<main>` has `id="contenido"`. |
| `.blog-button`, `.blog-button_variant_primary`, `.blog-button_variant_secondary` | `app/(frontend)/blog/blog.css` | Blog-specific buttons, intentionally shared by the listing and the article page. |
| `.platform-page`, `.platform-page__head`, `.platform-page__title`, `.platform-page__subtitle` | `platform.css` | The vertical layout of every platform page: 28 px gaps, 39.5 px balanced title, muted subtitle. |
| `.platform-card`, `.platform-card__title` | `platform.css` | White card with the card shadow. |
| `.platform-button`, `.platform-button_variant_secondary`, `.platform-button_variant_danger` | `platform.css` | Platform buttons. Secondary and danger draw their outline with `box-shadow: inset` so they measure exactly like the primary. |

| `.platform-theme` | `platform.css` | Set on `<body>` by the auth and platform layouts; scopes the light overrides. |

## Cross-cutting rules in `globals.css`

- **Reset.** Universal `box-sizing: border-box`, zero margins and paddings, headings without their own size, lists without bullets, media as block elements. Anything a component needs beyond that is the component's job.
- **Focus.** `:focus-visible { outline: 2px solid var(--color-primary) }` on the public site; `.platform-theme :focus-visible` switches to `--platform-accent-ink` because the plain orange does not contrast on light. Never write `outline: none` without a replacement.
- **Hover transitions.** Links, buttons, form controls, rows, articles and menu items animate `background-color`, `border-color`, `box-shadow`, `color` and `opacity` over `--transition-hover` (150 ms). The property list is explicit (`all` would animate layout changes). Under `prefers-reduced-motion: reduce` the transition is removed.
- **Selection.** `::selection` on the platform is a 30 % orange.

## Adding a stylesheet

1. Create `<component>.comp.css` (or `.section.css`) next to the component and import it there.
2. Start with the block selector; nest every element, modifier and media query under it with `&`.
3. Colours, fonts, shadows and the progress track come from tokens; if you need a value that has no token, add the token to the right theme file with a comment saying what it is for, rather than writing the hex in the component.
4. Public site: dark tokens by default; inside `.section_theme_light` use the `-on-light` variants. Platform: only `--platform-*`.
5. Keep the closed/hidden state inside the block (`.block_open`, `.block__panel_hidden`), never as a global `[hidden]` override.
6. No `!important`, no id selectors, no element selectors outside the block except for native controls inside a wrapper (`& .platform-field__control input`).
7. If a rule must apply to several components, it is a primitive: put it in the theme file and document it in the table above.
