# Styling & design tokens

The project uses **plain CSS** only: no Tailwind (it was removed and its preflight replaced by a hand-written reset), no CSS Modules, no CSS-in-JS. Each stylesheet belongs to a single component or page and is imported there, except the two theme files described here.

## Two products, two stylesheets

| File                          | Paints                                                         | Contains                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/(frontend)/globals.css`  | **Dark** — the public site                                     | The reset, the `--color-*` tokens, the board colours, base element styles (`html`, `body`, headings, links, forms), the global `:focus-visible` outline, the skip link, the hover transition rules and the `.section` / `.button` primitives.                                                                                                                                                                          |
| `app/(platform)/platform.css` | **Light and dark** — the authenticated area and the login page | The `--platform-*` tokens, each colour declared once as a `light-dark()` pair, and the `color-scheme` rules on `:root` that pick which of the two is drawn; `body.platform-theme` (which repaints the dark `body` from `globals.css`), a platform-coloured focus outline, and the `.platform-page` / `.platform-card` / `.platform-button` / `.platform-row-action` / `.platform-dialog` / `.platform-tag` primitives. |

Both files are global on purpose; every other stylesheet is scoped to its component.

The platform has **two themes**, and both are written in `platform.css`: a component's stylesheet reads the tokens and does not ask which theme it is drawn in (the one that does is the theme switch's own, `platform-user-menu.comp.css`, to show the row that fits). How the theme is chosen, stored and switched is in [Themes](/architecture/themes).

### Which layout loads what

| Root layout                 | Stylesheets                      | `<body>` class   | Font variables on `<html>`                               |
| --------------------------- | -------------------------------- | ---------------- | -------------------------------------------------------- |
| `app/(frontend)/layout.tsx` | `globals.css`                    | none             | `--font-gramatika`, `--font-suisse`, `--font-chessglyph` |
| `app/(auth)/layout.tsx`     | `globals.css` + `platform.css`   | `platform-theme` | the three above + `--font-sf-pro`                        |
| `app/(platform)/layout.tsx` | `globals.css` + `platform.css`   | `platform-theme` | the three above + `--font-sf-pro`                        |
| `app/global-not-found.tsx`  | `globals.css`                    | none             | public fonts                                             |
| `app/(payload)/layout.tsx`  | Payload's own CSS + `custom.css` | Payload's        | —                                                        |

`platform.css` always sits **on top of** `globals.css`: the reset, the element defaults and the transition rules come from the public sheet, and the platform sheet only swaps the palette and the font. That is why `body.platform-theme` exists: `globals.css` paints the body dark, and without that rule the scroll bounce on the platform would show black under the content.

## Tokens

Tokens are the only place a colour is chosen (plus the two layout tokens below, the measurements several stylesheets have to agree on). Component stylesheets use `var(--…)`; a bare hex value in a component is debt. The platform's and the access pages' stylesheets have none; the ones that remain are in the public site's and in `components/chess`, where all but `EloTable`'s are the fallback of a `--platform-*` token (`var(--platform-surface, #2b2723)`) for the public site, where those tokens do not exist. No task tracks them.

### Platform — `--platform-*` (`platform.css`)

Every colour is declared once, in the single `:root` block of `platform.css`, as `light-dark(<light>, <dark>)`, and `color-scheme` on that same `:root` decides which one is drawn (see [Themes](/architecture/themes)). The values themselves are drawn in Storybook (`npm run storybook` → **platform/foundations/Colours**: every token as a swatch, with its light and dark values and the comment written above it), read from the stylesheet, so they cannot drift from it; this table names the tokens and says what each family is for instead of copying the values. Which text may be written on which of them, with the contrast of every pair in both themes, is the page beside it, **Text on a surface** (see [Storybook › Foundations](/ui/storybook#foundations)).

In the light theme the brand's black keeps its value and changes role: `#16110d` goes from background to text. In the dark theme the canvas is a near-black of that family (`#14100d`) and the text is the public site's own (`#f2ede7`).

**The accent is by theme.** On a light background it is the brand's red, **`#a81e22`** — the one the blog, which is the public site's light section, already draws its logo, links and buttons in. On a dark background it is the brand's orange, **`#ff9143`**, the one the public site is built on. Both are the two halves of the same declaration (`--platform-accent: light-dark(#a81e22, #ff9143)`), and the rest of the `--platform-accent*` family follows it. That is why no stylesheet, comment or page of these docs names the platform's accent by its colour. What is written on a fill of the accent is `--platform-on-accent`: white on the light theme's accent, a near-black on the dark one's. A translucent accent is written over the token (`color-mix(in srgb, var(--platform-accent) 40%, transparent)`), never as an `rgba()` of its own, so it follows the token.

`--transition-hover` is read by the global transition rule with a `150ms` default; a component may set it to change or remove the duration.

`globals.css` sets `scroll-behavior: smooth` on `html`, inside `@media (prefers-reduced-motion: no-preference)` — whoever asked the system for less motion gets the jump without the glide —, and every layout's `<html>` carries `data-scroll-behavior="smooth"` with it: without that attribute Next warns, because during a route transition it restores the scroll and a smooth one would animate the jump instead of landing on it.

## The platform does not bounce

`:root:has(> .platform-theme)` carries `overscroll-behavior: none`. On the elastic overscroll of a trackpad the whole document slides, and the bar stuck to the top slides with it, which reads as the header coming loose. It goes on the **root**, the element that scrolls the document — on `<body>` it is the browser's choice whether to honour it — and only under the platform's layouts, so the public site keeps the bounce it was drawn with. The same rule sets `scroll-padding-top` to the height of the bar (70px at the platform's zoom, 116px below 1080px, where the bar wraps into two rows) plus 8px: the bar is stuck to the top, and without it a control reached with Shift+Tab, or the target of the skip link, is scrolled to under the bar instead of below it (WCAG 2.4.11). It applies to every scroll the browser does to bring something into view: sequential focus, a `focus()` called from code, `scrollIntoView` and the skip link's target. A scroller of its own needs its own: the lesson's column of lessons, whose chapter name is stuck to its top, sets one on `.lesson-outline__body`.

A panel that scrolls on its own says it again for itself: the lesson's column of lessons does, since there the bounce dragged its sticky chapter.

## Type and space

Every font size of the platform is one of ten tokens, and every gap, padding and margin one of twelve, declared in the `:root` of `platform.css` in real px. A stylesheet writes `var(--platform-type-sm)` or `var(--platform-space-3)` and never a px of its own for either: the thirty font sizes and two dozen gaps the stylesheets had drifted into are ten and twelve now.

| Scale | Tokens                                                                                                                                                                                               | Note                                                                                                                          |

| Type  | `--platform-type-2xs` 12, `-xs` 14, `-sm` 15, `-md` 16, `-lg` 17, `-xl` 20, `-2xl` 24, `-3xl` 32, `-4xl` 44, `-5xl` 52 — from 1536px: 13, 15, 16, 17, 18, 22, 26, 36, 48, 56                         | Four small steps a pixel apart, where nearly all the text is; the rest for headings and figures.                              |
| Space | `--platform-space-0-5` 2, `-1` 4, `-2` 8, `-3` 12, `-4` 16, `-5` 20, `-6` 24, `-8` 32, `-10` 40, `-12` 48, `-16` 64, `-24` 96 — from 1536px: the same up to 12, then 20, 24, 28, 36, 44, 56, 72, 108 | A 4px grid, and 2 for the tightest; the name is the multiple of 4. **From 1536px wide** (Tailwind's `2xl`), where there is room to spare, every token takes a step up: one `@media (width >= 1536px)` block after the `:root` of `platform.css` redeclares each with the larger value, so no stylesheet has to know. **One page keeps the base scale**: the lesson (`.platform-page_scale_base`, on its layout's page since 2026-10-06), whose board, column and notes were sized to it. The modifier repeats the base values under the same query, for everything inside the page — the fixed column of lessons too, since custom properties follow the DOM and not the box; the bar is outside the page and keeps the step. `platform-tokens.test.ts` checks the repeated values against `:root`'s. Storybook draws all of it (**platform/foundations** → Type scale, Spacing scale, Large screens), each step at its size with how often the stylesheets write it, and a piece of a screen at both scales side by side.

What stays in px, on purpose: a **hairline** of 1px in a gap, a padding or a margin, which is a line and not a space; a px **inside a `calc()` of geometry** (a mark's centre, a step of indentation), which belongs to what it measures; and the **board's coordinates** (9px), drawn inside a square where the smallest step crowds its corner. The four chess stylesheets the public site also draws (`ChessBoard` and its lazy wrapper, `StaticDiagram`, `EloTable`) write each token with the site's size as its fallback — `var(--platform-type-sm, 14px)` —, since the site does not load `platform.css`. `components/platform/type-and-space.test.ts` fails on any other font size or space in px, on a `zoom` and on a font named instead of read from a token ([Fonts](#fonts)).

**There is no zoom.** Until 2026-10-02 `body.platform-theme` carried `zoom: 1.1`, which drew everything a tenth larger: it was the way to ask for a bigger interface, not a figure to keep. The steps carry that enlargement, so text and spaces read as large as they did; the other lengths (widths, heights, icons, positions) were not recalculated and are drawn as written, which is a tenth smaller than under the zoom. With it went what the zoom required: a viewport unit is no longer divided by it, and `ChessBoard` no longer gives it back for chessground's subtree. The scripts that measure with `getBoundingClientRect()` still divide by `element.currentCSSZoom`, which is now 1 and keeps them right under any zoom an ancestor might carry.

Platform stylesheets name no font of their own: they use `var(--platform-font)`, `var(--platform-font-display)` for a title, `var(--platform-font-serif)` or `var(--platform-font-mono)`, or they inherit. The one exception is the ELO table (`components/chess/elo-table.comp.css`), which lives with the chess pieces but is drawn only on the public site, which does not load `platform.css`: its figures read the site's `var(--font-gramatika)`. `components/platform/type-and-space.test.ts` fails on any other `font-family`, and Storybook's «Type» page lists what is named, read from the stylesheets.

**The title of a page is Poppins** — «Mis cursos», «Mis estudios», the name of a course — through one rule in `platform.css`, so no block declares it:

```css
.platform-theme h1 {
  font-family: var(--platform-font-display);
}
```

Every page's title is drawn at **600**, which is the weight of the font's semibold. It is the `h1` each page opens with, and nothing else: everything under it, from a card's title to a section's heading, is the text font. A page that wants another font for its title says so in its own file and wins by specificity; that is also why an `h1` must NOT redeclare `--platform-font`, which is what four heading rules used to do. See [Stockfish, pieces & sounds](/chess/engine-and-assets#fonts--publicfonts) for the subsetting commands and licences.

## BEM, nesting and scoping

The naming is Yandex-style BEM and the scoping is native CSS nesting. Both are mandatory for every component stylesheet.

- **Block** = the component's root class, in kebab-case: `.study-card`, `.platform-table`, `.game-viewer`.
- **Element** = `block__element`: `.study-card__title`. Elements are never nested in the name (`.study-card__head__title` is wrong; use `.study-card__head-title`).
- **Modifier** = `block_key_value` or `element_key_value`: `.platform-button_variant_accent`, `.platform-table__cell_align_right`, `.progress-indicator_layout_stacked`. Boolean modifiers drop the value: `.site-header__dropdown_open`, `.logo__mark_hidden`.
- **One file per component**, named after it (`study-card.comp.css` next to `study-card.comp.tsx`) and imported from that component only.
- **Every rule nests under the root selector** with `&`, so nothing can leak out of the block. Media queries go inside the block too. The one exception is `@keyframes`: it is not valid inside a style rule (the browser drops it and the build warns), so it goes at the top level after the block, named `block-…` (`board-loading-hop`, `time-roller-enter`).
- **Desktop-first, on Tailwind's breakpoints.** The platform reflows at five widths only — `sm` 640, `md` 768, `lg` 1024, `xl` 1280, `2xl` 1536px — written in the range syntax: `@media (width < 1024px)` for what changes below a breakpoint, `(width >= 1536px)` for what changes from one. Pick the breakpoint where the layout breaks and write the query inside the element it changes. A height query (`(max-height: 620px)`, a screen too short for the lesson) is not a breakpoint and stays free. Until 2026-10-02 the stylesheets had drifted into nineteen widths (520, 620, 720, 900, 1080…); each went to the nearest of the five. `components/platform/breakpoints.test.ts` fails on any other width. The public site keeps its own.

A complete example (`components/platform/shared/empty-state/empty-state.comp.css`):

```css
.empty-state {
  border: 1px dashed var(--platform-border);
  border-radius: 8px;
  padding: 28px 24px;
  text-align: center;

  & .empty-state__title {
    margin: 0;
    font-size: 16.5px;
    font-weight: 600;
    color: var(--platform-text);
  }

  & .empty-state__description {
    margin: 6px 0 0;
    font-size: 15.5px;
    color: var(--platform-text-muted);
  }

  & .empty-state__action {
    display: inline-block;
    margin-top: 14px;
    font-size: 15.5px;
    font-weight: 600;
    color: var(--platform-accent-ink);
  }
}
```

Modifiers on the root use the compound form (`&.block_key_value`) so they still nest; a media query sits inside the element it changes. The first example is `components/chess/chess-board-lazy.comp.css`, abridged — note the token fallbacks: this component also renders on the public site, where the `--platform-*` tokens do not exist — and the second, `components/platform/shared/progress-indicator/progress-indicator.comp.css`, abridged.

```css
  max-width: 800px;

  & .chess-board-lazy__board {
    width: 58%;
    aspect-ratio: 1;

    }
  }

  & .chess-board-lazy__toolbar {
```


The React side mirrors this: modifiers are appended conditionally, and the class string is built in the component, never passed in from a parent (`className` props exist only on leaf primitives such as `EloTable` and the icons).

## Cards in the platform

A card — a panel, a table, a row of a list, a box of the game viewer — is **the surface on the page's canvas** (`--platform-surface` on `--platform-bg`: white on grey in the light theme, a near-black a step lighter than the canvas's in the dark one), over the card shadow where it has one. **It declares no outline.** The thin grey border cards had was there to tell them from a white page; the canvas is a grey now and the border is gone. In the dark theme, where a shadow separates nothing, the hairline comes back **inside `--platform-shadow-card`**, as a 1px ring of `--platform-border`: the token draws it, so a card's stylesheet is the same in both themes.

`--platform-border` is still what it was for everything else:

- a **rule inside** a card: between its head and its body, between the rows of a table;
- what a card draws **inside another** card, surface on surface, where the fill tells nothing;
- a **control**: a field, a quiet button, a chip (`--platform-border-strong` for the ones that are pressed);
- what **floats** over the page: a menu, a list, a calendar.

A card whose hover colours its edge (`StudyCard`, the explorer's games) keeps a `1px solid transparent` border, so the hover moves nothing.

## Corners in the platform

In the platform a corner is rounded **`8px`, or all the way**, with **`4px`** as the one exception, for a control too small for 8. It holds for anything — a card, a button, a field, a tag, a dialog, a menu, a cover — and whatever its size: a large card does not get a larger radius.

| Value          | When                                                                                                                                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `8px`          | Every corner that is rounded and is not a pill nor a circle.                                                                                                                                                                                                     |
| `4px`          | **Only a control of about 20px or less**, where 8 is all but a circle: a checkbox at 8px reads as a radio, as something one of which is chosen. On anything of a normal size, reaching for it is deciding a radius — which is what this rule is here to prevent. |
| `1000px`       | All the way: a pill, a progress track, a count.                                                                                                                                                                                                                  |
| `50%`          | All the way, for a circle: an avatar, a dot, a round button.                                                                                                                                                                                                     |
| `0`, `inherit` | No radius of its own: a side left square (`8px 8px 0 0`), a corner taken from the parent.                                                                                                                                                                        |

The rule covers `app/(platform)`, `app/(auth)`, `components/platform`, `components/auth` and `components/chess` — the chess pieces are shared with the public site, but they are drawn with the platform's tokens and are what a lesson is made of. `components/platform/border-radius.test.ts` reads every stylesheet under them and fails on a value that is none of the above, so `npm test` is what catches a `10px`. The rest of the public site is not under it: its radii are its own.

## Popups come in and go out animated

Nothing that opens over the page appears or disappears in a cut. A menu, a list, a calendar or a tip takes **160 ms to come in** (`ease-out`) and **120 ms to go out** (`ease-in`), and both are switched off under `prefers-reduced-motion`. What keeps the popup on screen while it leaves depends on what it is:

| Popup                        | How its exit is kept on screen                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A native `<dialog>`          | It inherits its motion from `.platform-dialog`, the frame under `PlatformPopup` and `PlatformConfirmPopup`, in CSS alone, and no popup animates on its own. The dialog has its own numbers: one `transition`, the same in both directions, of the opacity over 160 ms and of a 14px rise with `scale(0.98)` over 200 ms. `@starting-style` gives the entry the values it starts from, and `allow-discrete` on `display` and `overlay` keeps the dialog visible, and in the top layer, for those 200 ms; the backdrop fades over the same 200 ms. |
| A menu mounted conditionally | The component keeps it mounted with `useLingering` (`components/chess/game-viewer/use-lingering.hook.ts`, whose `POPUP_EXIT_MS` is the 120 ms) and renders it once more with a `_state_closing` modifier, which plays the exit keyframes: the bar's menu, a syllabus row's menu, the game viewer's two menus.                                                                                                                                                                                                                                    |
| A Radix popup                | Radix keeps the content mounted while an animation runs on `data-state="closed"`, so the stylesheet animates on `data-state` and the component does nothing: `PlatformSelect`, `PlatformDatePicker`, `PlatformInfoTip`.                                                                                                                                                                                                                                                                                                                          |

The entry and exit keyframes are the block's own (`platform-select-in`, `platform-select-out`), at the top level of its stylesheet.

## The adventure's paper

«Jugar»'s adventure (`components/adventure/`, [the components](/components/adventure)) is a notebook on a desk, drawn in cut paper, and it has a palette and four fonts of its own. They live in ONE stylesheet, `components/adventure/adventure.css`, in the `.adventure` block: every piece of the adventure sits under an element with that class, which is where the tokens are declared and so where they are read.

- **`--adventure-*`, not `--platform-*`.** The paper (`paper`, `cream`, `cream-bright`, `kraft`, `kraft-pale`, the two tickets), the inks (`ink`, `ink-soft`, `graphite`, the `brick` and its deep one for the small print on the kraft), the thread and the brick of a filled tag, the sage and the ochre, the desk (`wood`, `leather`, what is written on them) and two shadows. The buttons and popups inside the adventure are still the platform's, drawn with the platform's tokens, so a stylesheet of the adventure may read both families; a stylesheet of the platform never reads `--adventure-*` (`adventure-tokens.test.ts` fails on it).
- **Every colour is a `light-dark()` pair.** The dark theme is the same notebook at night: ink-blue paper under a lamp, the cream turned into the ink and the ink into the cream. The pair is written side by side, as in `platform.css`, and `components/adventure/adventure-tokens.test.ts` keeps what `platform-tokens.test.ts` keeps for the platform: no single value, no token used and never declared, and 4.5:1 for every text on what it is written on, in both themes — the list of pairs the paper uses, and every rule that sets its own colour and its own fill. The tests read the block with the same `lib/platform-tokens.ts`, which takes a `{ prefix, selector, file }` (`ADVENTURE_TOKEN_SET`) and defaults to the platform's.
- **`color-scheme` is on the same element as the tokens**, as on the `:root` (Lightning CSS declares its `light-dark()` helper variables where it finds it), and the two nested rules `:root[data-theme="light"] &` and `:root[data-theme="dark"] &` repeat the person's choice there, because the element's own `color-scheme: light dark` would otherwise outrank the one set on the `:root` and the paper would follow the machine whatever the person chose.
- **Four fonts**, `--adventure-font-title` (Fraunces), `-note` (Caveat), `-hand` (Kalam) and `-data` (IBM Plex Mono), each with a real fallback, since none is preloaded. All four are under the SIL Open Font License, with the text beside each in `public/fonts/<name>-OFL.txt`, and are Google Fonts' own Latin subset. Storybook declares the same four with `@font-face` in `.storybook/preview.css`.
- **What the platform's other rules say of the adventure.** Its stylesheets are read by the breakpoints test (the five Tailwind cuts, range syntax) and the reduced-motion test, like the platform's. The corner, type-scale and space-scale tests (`border-radius.test.ts`, `type-and-space.test.ts`) do not read them: the paper draws its own sizes and shapes.

## Cross-cutting rules in `globals.css`

- **Reset.** Universal `box-sizing: border-box`, zero margins and paddings, headings without their own size, lists without bullets, media as block elements. Anything a component needs beyond that is the component's job.
- **Focus.** `:focus-visible { outline: 2px solid var(--color-primary) }` on the public site; `.platform-theme :focus-visible` switches to `--platform-accent-ink`, the accent as text in whichever theme is drawn, because the plain orange does not contrast on the light one. Never write `outline: none` without a replacement, and a replacement reaches 3:1 against what is around it (WCAG 1.4.11): a border that turns the accent does, the accent's soft tint as a ring does not (1.2:1), so a control with no border of its own keeps the platform's ring.
- **Hover transitions.** Links, buttons, form controls, rows, articles and menu items animate `background-color`, `border-color`, `box-shadow`, `color` and `opacity` over `--transition-hover` (150 ms). The property list is explicit (`all` would animate layout changes). Under `prefers-reduced-motion: reduce` the transition is removed.
- **Selection.** `::selection` on the platform is the accent at 30 %.
- **Scrollbar gutter.** `html { scrollbar-gutter: stable }` reserves the scrollbar's room whether or not the page scrolls, so a short page (a segment's loading fallback) and the long one that replaces it keep the same width and nothing centred with `margin: auto` — the platform's bar, the content — jumps sideways when the bar appears. Global because the public site centres the same way. With overlay scrollbars (macOS by default) the gutter is 0 and nothing changes; Safari ignores the property.

## Adding a stylesheet

1. Create `<component>.comp.css` (or `.section.css`) next to the component and import it there.
2. Start with the block selector; nest every element, modifier and media query under it with `&`.
3. Colours, fonts, shadows and the progress track come from tokens; if you need a value that has no token, add the token to the right theme file with a comment saying what it is for, rather than writing the hex in the component. A platform colour is declared with its two values (see [Themes › Adding a colour](/architecture/themes#adding-a-colour)).
4. Public site: dark tokens by default; inside `.section_theme_light` use the `-on-light` variants. Platform: only `--platform-*`.
5. Keep the closed/hidden state inside the block (`.block_open`, `.block__panel_hidden`), never as a global `[hidden]` override.
6. No `!important`, no id selectors, no element selectors outside the block except for native controls inside a wrapper (`& .platform-form__field > input`).
7. If a rule must apply to several components, it is a primitive: put it in the theme file and document it in the table above.
