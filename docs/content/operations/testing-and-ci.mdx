# Testing & CI

## Vitest

`vitest.config.mts`:

- environment `node`; tests are `**/*.test.{ts,tsx}` outside `node_modules`, `.next`, the generated Prisma client, `docs/` and `storybook-static/`;
- alias `@` → repository root, and `server-only` → `lib/testing/server-only.stub.ts` (Next provides that package at bundle time; in Node it would throw and block importing any service);
- coverage (`npm run test:coverage`, v8) over `lib/**`, `services/**`, `constants/**`, `hooks/**`, excluding generated code, fixtures, tests and `*.types.ts`. The report lands in `coverage/` (git-ignored, ESLint-ignored).

Conventions:

- Tests are deterministic: dates come in as parameters or are built with local constructors; nothing reads the clock.
- Anything that needs Prisma or a request is not unit-tested; instead the logic is extracted into a pure module (`*-rules.ts`, `*-transitions.ts`, `reorder.ts`) and that module is tested. Manual verification of panels is recorded in `TODOS.md`.
- Component tests (`.test.tsx`) are possible with the current config but none exist yet.

```bash
npm test                  # one run
npm run test:watch        # watch mode
npm run test:coverage     # coverage report in coverage/
npx vitest run lib/chess  # a folder
```

## Static checks

- `npm run typecheck` — `next typegen && tsc --noEmit` (the route types in `.next/types` are generated first, which is what a fresh CI checkout lacks), strict, `noUnusedLocals`, `noUncheckedIndexedAccess`, target ES2022. `docs/` is excluded (it has its own `tsconfig.json`).
- `npm run lint` — ESLint 9 flat config with `eslint-config-next` (core web vitals + TypeScript) plus the recommended rules of `eslint-plugin-jsx-a11y` as errors on every `.tsx` (a click handler on a `<div>`, an image without `alt`, a role without its ARIA, a label without a control…; `eslint.config.mjs` lists them and says why `no-autofocus` is left out); ignores `.next`, `public` (design-kit scripts), the generated Prisma client, `coverage` and `docs`.
- `npm run format:check` — Prettier 3, `printWidth: 120`, over every file git does not ignore (`--ignore-path .gitignore`): code, CSS, the docs' MDX, the workflow and `.claude/settings.json`. `npm run format` rewrites what it reports.

## Continuous integration

`.github/workflows/ci.yml` runs on every push to `main` and every pull request, on Node 20 with npm cache:

```yaml
- run: npm ci
- run: npm run db:generate # needs only a syntactically valid PLATFORM_DATABASE_URL
- run: npm run format:check
- run: npm run lint
- run: npm run typecheck
- run: npm test
```

The steps run in order and the first failure skips the rest: a file that drifted from Prettier fails the job before lint, types or tests have run, which is why `format:check` is part of the [definition of done](/conventions#definition-of-done).

It does **not** run `next build`: static generation reads Payload (home, blog, sitemap) and the platform database, neither of which exists in CI. The deployment is what validates the build. The docs site is not built in CI either; build it locally (`cd docs && npm run build`) when you change it.

## Manual checks worth repeating

- Log in with the three demo accounts and open a page of each panel with the wrong role: it must redirect without rendering data.
- Import a large PGN (hundreds of games) into a study and search a position in the explorer.
- Save a Global in `/admin` and reload `/`: the change must be visible immediately.
- Run Lighthouse against `npm run build && npm run start` before and after performance work.
