# Backlog (IMPROVEMENTS & todos)

Three files in the repository root hold the backlog: `IMPROVEMENTS.md`, `TODOS.md` and `WARNINGS.md`. They are written in English, like the code comments, and they are the source of truth: this page explains what each one is for and how an entry is written, and deliberately lists none of them, because a list copied here would go stale with the next commit.

## Where they live

The three files exist **only in the local copy** of the repository: `.gitignore` names them, so they are never pushed and a fresh clone does not have them. A number such as `#17` or `T16` in a commit message, a comment or a page of this site refers to an entry of those local files.

## `IMPROVEMENTS.md`

Prioritised technical debt and improvements: what somebody found and did not fix. Every entry has a number, an **area** tag (Security, Data, CSS, UX, DX, Ops…), a **priority** (low · medium · high · extreme) and a note on how to approach it. Resolved entries stay in the file with a strikethrough title and a summary of what was done, so the same idea is not reopened. When you find something you will not fix now, add an entry; when you fix one, mark it resolved as part of the same change.

## `TODOS.md`

Concrete, mechanical tasks with a full specification, meant to be executed without further design (by a junior developer or a cheaper model). Each task has a number (`T16`) and names the files, the expected change and the checks to run. Finished tasks stay in the file with what actually changed.

## `WARNINGS.md`

The risks the project takes on knowingly — a doubtful licence, for example. An entry says **what** the risk is, **why** it was accepted and **how to back out** of it. It is not debt waiting for its turn: it is a decision, written down so that whoever inherits it knows it was made and what undoing it takes. A page of this site that describes something carrying such a risk says so and points at the file (the board sounds in [Stockfish, pieces & sounds](/chess/engine-and-assets), the commentary of the seeded courses in [Scripts & seed](/operations/scripts-and-seed)).

## Working with the backlog

- Read `IMPROVEMENTS.md` before starting a refactor: the reasoning behind a decision is often recorded there (why the rate limit lives in Postgres, why `/` cannot read cookies, why the seed guard exists).
- Debt found and resolved is part of the change: the entry is added, or marked resolved, when the code and its documentation are committed, although the files themselves stay out of the commit (see [Conventions](/conventions#documentation-and-debt)).
- The three files are the source of truth; this documentation explains them but never replaces them.
