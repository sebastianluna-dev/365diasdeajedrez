# Backlog (IMPROVEMENTS & todos)

> Since 2026-09-24 `IMPROVEMENTS.md`, `TODOS.md` and `WARNINGS.md` live only in the local copy of the repository: they are gitignored and never pushed. The numbers below refer to entries in those local files.

Two files in the repository root hold the backlog, and both are the source of truth. This page explains how they work and summarises what was open on 2026-09-21.

## `IMPROVEMENTS.md`

Prioritised technical debt and improvements. Every entry has a number, an **area** tag (Security, Data, CSS, UX, DX, Ops…), a **priority** (low · medium · high · extreme) and a note on how to approach it. Resolved entries stay in the file with a strikethrough title and a summary of what was done, so the same idea is not reopened. When you find something you will not fix now, add an entry; when you fix one, mark it resolved in the same commit.

## `TODOS.md`

Concrete, mechanical tasks with a full specification, meant to be executed without further design (by a junior developer or a cheaper model). Each task names the files, the expected change and the checks to run. Finished tasks stay in the file with what actually changed.

## Working with the backlog

- Read `IMPROVEMENTS.md` before starting a refactor: the reasoning behind a decision is often recorded there (why the rate limit lives in Postgres, why `/` cannot read cookies, why the seed guard exists).
- The two files are the source of truth; this documentation summarises them but never replaces them.
