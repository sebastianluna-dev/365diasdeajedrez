# Scripts & seed

All scripts run with `tsx` outside Next, load `.env.local` then `.env`, and build their own `PrismaClient` with `@prisma/adapter-pg` (the app's singleton is `server-only`). They fail fast if `PLATFORM_DATABASE_URL` is missing.

## `prisma/seed.ts` — `npm run db:seed`

Idempotent seed of the platform database: catalogs by `upsert(code)` (the levels by `slug`, with `seedLevels`, because their rows carry a description and an Elo range), domain rows by fixed ids or natural keys, so running it twice never duplicates.

What it creates (data in `prisma/seed-data.ts`):

- every catalog value (`seedCatalog` for `[code, label]` pairs; `seedCatalogRows` for a catalog with more columns, like `ContentType` with its `shortLabel` and `description`) and the topic tree;
- three demo accounts (student, teacher with an active `Teacher` row, staff) — the password is only set when the account has none;
- an author, the courses with chapters, lessons (PGN or linked games), topics and exercises derived with the same `deriveExerciseData` the staff panel uses; the role the author signs each course with (`SeedCourse.authorRole`, «Autor del contenido» by default) and its «Procedencia del recurso» (`SeedCourse.sources`);
- studies and games for the demo student (positions indexed with `indexGamePositions`), shared collections;
- classes with participants, blocks and a transcript, a teacher–student assignment;
- activities and the rebuilt `UserStatDaily` aggregates.

Environment switches:

| Variable                        | Effect                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| `PLATFORM_DEMO_PASSWORD`        | Password for the demo accounts (default `ajedrez365`).                                           |
| `ALLOW_DEMO_SEED=1`             | Allows seeding a **non-local** database with the default password. Test databases only.          |
| `SEED_NOW=2026-09-01T18:00:00Z` | Reference instant; without it, today at 18:00 UTC. Pin it to reproduce a database byte for byte. |
| `NODE_ENV=production`           | Treated as remote: the guard applies.                                                            |

The guard: if the database host is not `localhost`/`127.0.0.1`/`::1` (or `NODE_ENV=production`) and the password is the repository default and `ALLOW_DEMO_SEED` is not `1`, the seed throws before writing anything.

After a seed, run `npm run collections:by-chapter` if you need the lessons' own PGNs to be materialised as games in chapter collections (the script is idempotent and documents why it uses one short transaction per game).

### What a second seed finds

The seed is not transactional and is meant to be run again on a database the app has already written to. Two things follow.

**It replaces what it describes.** For every course in `COURSES`, the chapters, lessons and sources that are not in the data are deleted before the rest is written. A chapter added to a seeded course from the staff panel — an introduction, a closing — is gone after the next seed. Courses created from the panel are never touched.

**It adopts the collections the app created.** Two kinds of `GameDatabase` are also created by the app under ids of its own, and each is unique by something that is not the id: a chapter's collection (`@@unique([chapterId])`, created by `collections:by-chapter`) and a user's default study (`game_database_one_default_per_user`, created with the account by `createDefaultStudy`). Inserting the seed's row next to them would break the index, so the seed looks the existing row up, writes onto it and translates its own id into the real one for the shares, the games and the position index that point at it. Until 2026-09-28 it did not, and a second seed stopped at the first of those rows with `P2002`.

### Courses that come from a book

A course whose content is somebody else's book lives in its own module under `prisma/seed-courses/`, with its data file in `prisma/seed-courses/data/`. The module does not write the content: it validates the file and translates it into a `SeedCourse`. To change the content the file is replaced.

| Module                        | Data file                                      | What it is                                                                                                                                                                       |
| ----------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `think-like-a-grandmaster.ts` | `think-like-a-grandmaster.import.json`         | Kotov's _Piense como un gran maestro_: 162 diagrams over the book's 5 chapters, one position per lesson, plus a collection of 13 illustrative games.                             |
| `my-60-memorable-games.ts`    | `my-60-memorable-games.pgn` (a Lichess export) | Fischer's _Mis 60 memorables partidas_: one whole annotated game per lesson, in three chapters by stage (1957–1959, 1960–1962, 1963–1967). No collection: the lessons ARE the games. |

`my-60-memorable-games.ts` in detail:

- **The file is the export of the study** `https://lichess.org/study/Wq1xlajv`, verbatim. It carries **58 of the book's 60 games** — 59 and 60 are missing — and three reference games that the notes to game 55 cite. The course says so: the reference games are named «Partida de referencia N» and are not counted among the sixty.
- **`GAMES` is a correction table**, one entry per chapter of the study in its order, keyed by the study's `ChapterName`. The study is an amateur transcription: it misspells several players and attributes game 48 to Donald Byrne when it is Robert's. The lesson's title is rebuilt from the table and never read off the study's; every entry that departs from the study says why in `correction`. **The PGN itself is not touched**, typos included.
- **The seed refuses a file that does not match the table** (count, order, `ChapterName`, a repeated or out-of-range game number), so replacing the export cannot silently reorder the games or bring a title nobody reviewed.
- **Lesson ids** are `f10000004g<number>` for the book's games and `f10000004r<n>` for the reference ones: a game keeps its id whatever its place in the chapter.
- The board is set from **Fischer's side**, the five games the book is known for (17, 18, 39, 48, 58) are `isPriority`, and the academy signs the course as «Adaptación digital».
- **Three sources**, because they are three things: the original work (_My 60 Memorable Games_, Simon & Schuster, 1969), the Spanish edition the commentary is translated in (La Casa del Ajedrez, ISBN 9788412510034) and the study. The Spanish edition has **no year**: Casa del Libro gives 2023 and Open Library 2022 for the same ISBN, so `publicationYear` is null and the disagreement is written in the notes.
- `my-60-memorable-games.test.ts` holds all of the above, and that every one of the 61 games is read whole by `parsePgnTree` with no warning, which is what an illegal move in the transcription would raise.

The commentary of both courses is third-party text still in copyright: fine for the academy's internal use, not for publishing without a licence. `WARNINGS.md` has the entry.

## `scripts/platform-user.ts` — `npm run user:*`

```bash
npm run user:create   -- alumno@correo.com "Nombre Apellido"   # asks for the password without echo
npm run user:password -- alumno@correo.com                      # new password + closes all sessions
npm run user:list                                               # accounts, has-password, open sessions
```

Passwords are never accepted as arguments (they would end up in the shell history); use `PLATFORM_USER_PASSWORD` for non-interactive runs. Validation uses the same `passwordProblem()` and `hashPassword()` as the app, and `user:create` enrols the student the way the staff panel does: the account and its "Mis partidas" study go in one transaction (`createDefaultStudy`).

## `scripts/index-game-positions.ts` — `npm run positions:index`

Fills `GamePosition` for games saved before the index existed, in batches of 200. `-- --all` deletes and regenerates every game's index; run it after changing FEN normalisation or the hash algorithm.

## `scripts/migrate-chapter-collections.ts` — `npm run collections:by-chapter`

One-off data migration from course-level collections to **chapter** collections (the SQL migration only added the column). Creates the chapter collections, moves games to the chapter of the lesson that references them (or the first chapter), and registers each lesson's own PGN as a game linked to it. Idempotent, resumable, `--dry` mode. Uses one short transaction per game because long interactive transactions with the pg adapter were observed to return `null` from `create` without throwing.

## `scripts/rebuild-daily-stats.ts` — `npm run stats:rebuild`

Rebuilds `UserStatDaily` from `UserActivity` through `services/shared/daily-stats.ts` (the same function the seed uses), for every account or for one (`-- <email>`). The aggregate is derived, so this is the answer whenever the bucketing changes — on 2026-09-21 the day moved from UTC to the study day, `America/Mexico_City` — or the two tables are suspected to have drifted apart. Each account is rebuilt in one transaction.

## `scripts/make-board-sounds.ts` — `npm run sounds:make`

Not what the viewer plays today (that is lichess's `.mp3`, see [Stockfish, pieces & sounds](/chess/engine-and-assets)); this is the way out if they ever have to go. Writes `public/sounds/move.wav` and `capture.wav` by modal synthesis: a seeded noise burst through a two-pole low-pass (the strike) rings a bank of two-pole resonators (the wood), each with its frequency, level and decay in the script's `SPECS`. No third-party audio in the repository. Change the specs and run it again; the output is byte-for-byte reproducible. The values were tuned against measurements of lichess' standard recordings, never their samples. To switch: point `SOURCES` in `components/chess/game-viewer/move-sound.ts` at the `.wav` files.

## `scripts/sync-pieces.ts` — `npm run pieces:sync`

Regenerates `public/pieces/*.svg` from chessground's cburnett CSS (adds `viewBox`). Run after upgrading `@lichess-org/chessground`.

## Adding a script

- Put it in `scripts/`, add an `npm run` alias, start with the `dotenv` lines and the connection guard.
- Share logic with the app through pure modules or modules that avoid `server-only` (`password.ts`, `logger.ts`, `position-hash.ts`, the catalog constants, `game-positions.service.ts` and `daily-stats.ts`, which take the client as a parameter).
- Prefer idempotent, resumable behaviour and a `--dry` flag for anything that writes.
