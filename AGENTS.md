# Convenciones del proyecto

Resumen de lo que explica `README.md` («Architecture in brief»). Si algo de aquí y el código discrepan, manda el código.

- **Tres piezas en una app Next 16**: sitio público `app/(frontend)`, CMS Payload `app/(payload)` (`/admin`, base `DATABASE_URI`) y plataforma autenticada `app/(platform)` + `app/(auth)` (Prisma 7 sobre `PLATFORM_DATABASE_URL`, una base distinta y sin tablas compartidas).
- **Datos**: la UI nunca llama a Prisma; siempre `services/<dominio>/{service,mapper,types}.ts` (más `.actions.ts` para server actions). Catálogos con `code` en vez de enums. El PGN es la fuente del contenido ajedrecístico.
- **Auth**: `lib/platform-auth/current-user.ts` es el DAL; toda página y server action de la plataforma resuelve al usuario ahí, nunca desde el cliente. `requireTeacher()`/`requireStaff()` abren cada página y action de `/profesor` y `/administracion`. `proxy.ts` sólo mira si existe la cookie. Una ruta nueva de `app/(platform)` se añade a `PROTECTED_PATH_PREFIXES` y al matcher del proxy (`proxy.test.ts` lo vigila).
- **Archivos**: kebab-case con sufijos `.comp.tsx`, `.section.tsx`, `.hook.ts`, `.const.ts`; named exports (default sólo en archivos de App Router); sin barrels, imports `@/...`.
- **Formularios de la plataforma**: los controles van sobre [Radix Primitives](https://www.radix-ui.com/primitives) (paquete `radix-ui`, sin estilos: se dibujan con nuestro BEM y tokens, nunca Radix Themes) a través de las piezas de `components/platform/shared/`: `PlatformForm`/`PlatformFormField`/`PlatformFormGroup` (formulario, campo con mensajes de validez y campo de grupo), `PlatformSelect` y `PlatformChoiceCards` (radio dibujado como tarjetas). Un formulario nuevo usa esas piezas; los que aún usan `FormField` con controles nativos se migran cuando se tocan. Los `<select>` nativos ya no existen en la plataforma: todo desplegable es `PlatformSelect` (con `size="compact"` dentro de `FormField`, `emptyOption` para la opción «ninguno» que envía `""`, `groups` en vez de `<optgroup>`). El `<dialog>` sigue siendo nativo, y por eso el select no se porta a `<body>`.
- **Componentes**: Server Components por defecto; `"use client"` sólo en la hoja que tiene el estado. Imágenes con `next/image`, nunca `<img>`. Copy en español. `components/` es espejo de `app/`: `site/`, `platform/` y `auth/`, cada uno con `sections/` (secciones de página) y `shared/` (piezas que reutilizan varias secciones de ese producto); `chess/` e `icons/` son de todos. Sin carpetas `common`.
- **Idioma**: **todo comentario va en inglés**, esté donde esté: código, CSS, tests, scripts, `prisma/schema.prisma`, workflows, `.env.example`, `.gitignore` y cualquier otro archivo de configuración; como los identificadores. El copy que ve el usuario (y las URLs) sigue en español, así que un comentario que cite un rótulo lo cita tal cual. Única excepción: los archivos generados (`payload-types.ts` reproduce las descripciones de los campos del CMS, que son copy) no se tocan a mano.
- **CSS**: BEM estricto (`bloque__elemento`, modificador `_clave_valor`), un archivo por componente y TODAS sus reglas anidadas bajo el selector raíz con nesting nativo (`&`), media queries dentro del bloque, desktop-first. Excepción: `@keyframes` no se puede anidar y va al nivel superior, con el nombre del bloque como prefijo. Todo popup entra y sale animado (160 ms de entrada, 120 de salida, ambos apagados bajo `prefers-reduced-motion`): los `<dialog>` lo heredan de `.platform-dialog`; un menú que se monta condicionalmente se mantiene montado durante la salida con `useLingering` (`components/chess/game-viewer/use-lingering.hook.ts`) y un modificador `_state_closing`; una lista de Radix anima sobre `data-state`. Tokens `--color-*` (`app/(frontend)/globals.css`) y `--platform-*` (`app/(platform)/platform.css`). Sin Tailwind ni CSS-in-JS.
- **Deuda**: lo que se encuentra y no se arregla va a `IMPROVEMENTS.md` (área, prioridad y cómo abordarlo); las tareas mecánicas, a `TODOS.md`; los riesgos que el proyecto asume a sabiendas (una licencia dudosa, por ejemplo), a `WARNINGS.md` con qué es, por qué se aceptó y cómo dar marcha atrás. Los tres están en inglés y **sólo existen en la copia local**: están en `.gitignore` y nunca van al remoto, así que un clon nuevo no los tiene.
- **Documentación**: la larga, en inglés, vive en `docs/` (sitio Nextra con su propio `package.json`; `cd docs && npm run dev`). **Todo cambio importante se documenta en el mismo commit**, no después: comportamiento, convenciones, rutas, modelo de datos, scripts, variables de entorno o una decisión que merezca quedar escrita. La página de `docs/` que cubra el área tocada; `README.md` (la referencia rápida del repositorio, en inglés) si cambian puesta en marcha, scripts o rutas; `AGENTS.md` si el cambio ES una convención; `IMPROVEMENTS.md`/`TODOS.md` para la deuda encontrada o resuelta.
- **Antes de dar algo por terminado**: `npm run typecheck`, `npm run lint` y `npm test` en verde, y la documentación del área tocada actualizada (si cambiaron páginas de `docs/`, `cd docs && npm run build`). Rendimiento, siempre contra `npm run build && npm run start`, nunca contra `next dev`.
